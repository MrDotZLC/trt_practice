# C++ 注释规范

当为 C++ 代码添加、修改或审查注释时，遵循以下规则。

## 必须注释的地方

1. **非直观逻辑**：任何需要读第二遍才能理解的代码，必须解释设计意图。
2. **魔数 / 硬编码常量**：说明来源和含义。
   ```cpp
   const int kMaxSeqLen = 4096;  // TRT engine 构建时的最大序列长度，与 model config 一致
   ```
3. **Workaround / 兼容性处理**：说明为什么这么做、什么条件下可以移除。
   ```cpp
   // TRT 10.x 的 BF16 binding 需要手动 pad 到 8 的倍数，否则 setTensorAddress 会越界
   // TODO: 升级到 TRT 11 后确认此问题是否修复
   ```
4. **算法 / 公式**：涉及数学推导、采样策略、量化公式时，给出简要推导或引用来源。
5. **边界条件**：对输入的特殊约束、异常分支的原因。
6. **公共 API**：头文件中的函数 / 类必须有注释说明用途、参数、返回值。

## 禁止注释的地方

1. **复述代码**：代码本身已表达清楚的逻辑，禁止再写一遍。
   ```cpp
   // 错误示范
   i++;  // i 自增 1
   ```
2. **逐行翻译式注释**。
3. **临时性调试注释**：`// test`、`// debug` 等在提交前必须清除。
4. **过时的注释**：修改代码时必须同步更新注释，宁可不写也不要留错误注释。

## 判断标准

如果一段代码删掉注释后，一个有经验的 C++ 工程师需要超过 30 秒才能理解意图，就应该有注释。

## 语言

统一使用中文。不要在同一个文件里混用中英文注释，必要的英文术语作为专有名词可保留。
