# Analysis

> **性质**：历史分析回填（2026-10-01）。来源：本目录 `future_iterations.md` §5.1 与
> `future_iterations_development_plan.md` §2.1。

## Current Architecture

推理运行时只收发 token id：它能做数值推理，但**没有"文本进 / 文本出"的路径**——文本与推理
之间那一环始终缺位。仓库里已有的分词器实现与目标模型的词表**不对齐**。

## Data Flow

```text
文本 →（分词器）→ token id → 既有推理路径 → token id →（分词器）→ 文本
          ↑
    需要两个数据文件：词表 + 合并规则（都在仓库外的本地缓存）
```

## Relevant Modules

| 模块 | 开工时状态 |
|---|---|
| 目标模型的字节级分词器 | 不存在 |
| 公共 JSON 解析器 | **不支持 `\uXXXX` 转义**——而词表 key 全是这种形式（前置障碍） |
| 参考数据 | 不存在（没有可信的标尺） |

## Existing Limitations

1. 没有文本入口/出口，端到端只能用 token id。
2. 载入接口的入参只有一个路径，而字节级分词器**需要两个文件**。
3. 公共 JSON 解析器缺转义支持 → 词表读不进来。

## Extension Points

- **分词器子类**：`Load` 的入参语义由子类决定（本条目把它解释为"目录"），基类不动。
- **参考数据固化**：把独立实现导出的 golden 落盘入库，成为长期标尺。
- **公共组件修复**：`\uXXXX` 支持一旦补上，后续所有需要读这类 JSON 的场景都受益。
