# Project Summary

> **性质**：历史交付总结回填（2026-10-01）。来源：本目录 `future_iterations_test_plan.md` §2.1。

## Problem

框架只有 token-id 出入口，没有"文本进 / 文本出"的路径；且仓库里没有与目标模型词表对齐的分词器，
公共 JSON 解析器还读不了带转义的词表。

## Solution

实现字节级分词器（词表 + 合并规则两个数据文件），用独立参考导出的 golden 文件作为标尺，
并补上公共解析器的转义支持。

## Architecture

```text
文本 → 预切分 → 字节级映射 → 按合并优先级归并 → token id → 既有推理路径
token id → 字节序列 → 文本
标尺：独立参考实现导出的 golden（入库，含环境与来源校验）
```

## Implementation

分词器实现（两个数据文件）→ golden 导出脚本 → host 用例（装载/负例/基础/空白/多语言/长文本/解码/边界）
→ 参考自证用例 → 公共解析器转义支持（实现期追加）。

## Performance

**不适用**。

## Limitation

- 数据文件**不入库**（在仓库外的本地缓存）；缺文件时用例跳过并打印探测结果。
- **只对参考给出的 ids 判解码可逆性**：任意 ids 不可逆是字节级分词的固有性质。
- 另一套分词器实现（SentencePiece 系）当时仍是**未验证件**（无资产、无用例、无调用方）。
