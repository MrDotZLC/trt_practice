# Design

> **性质**：历史设计回填（2026-10-01）。从 `docs/future_iterations_development_plan.md` §2.1
> 与 §0.5 的决策项抽取，**未新增当时的决定**。

## Overview

实现与目标模型词表一致的字节级分词器，让框架具备"文本进 / 文本出"的路径。

## Architecture

```text
文本 ──(分词器)──→ token id ──(既有推理路径)──→ token id ──(分词器)──→ 文本
                     ↑
              词表 + 合并规则两个数据文件（仓库外，本地缓存）
              独立参考实现导出 golden（入库，作为标尺）
```

## Module Design

| 决策 | 选择 | 为什么 |
|---|---|---|
| **F1 数据文件放哪** | **不入库**，由环境 / 构建变量指向（默认先看模型目录，再看本地缓存）；缺文件时**跳过并打印探测结果** | 与"大产物不入库、换机器按表重建"的既有规矩一致；HF 缓存被清理时用例跳过而不是失败 |
| **F2 载入接口如何承载两个文件** | **不改基类**：子类把入参解释为**目录** | 不动已交付接口，避免改动扩散到既有分词器实现 |
| **F3 参考数据怎么固化** | **Python 侧导出 golden 文件**（含文本 + ids + 生成环境），C++ 侧读它比对；另有来源校验用例 | 与"参考实现唯一 + 自带断言 + host 侧 meta-test"的既有约定一致；golden 体积小、它是标尺，入库不违反"大产物不入库" |

## Data Structure

```text
golden 文件 = 样本（文本 + ids）+ 生成环境（库版本 / 是否离线）+ 来源校验字段
```

## Runtime Flow

```text
装载：目录 → 词表 + 合并规则 → 就绪（缺任一文件即失败，不抛异常、不降级）
编码：预切分 → 字节级映射 → 按合并优先级归并 → ids
解码：ids → 字节序列 → 文本（只对参考 ids 判可逆性，任意 ids 不可逆是固有性质）
```

## Resource Lifecycle

- 数据文件在仓库外，生命周期由本地缓存决定；用例缺文件时**显式跳过并打印探测结果**。
- golden 入库，作为长期标尺。

## Performance Consideration

不涉及性能；关注点在**语义正确性**（逐 token 全等）。

## Trade-off

| 决策 | 说明 |
|---|---|
| 与第三方分词库的关系 | 实现自包含，不在运行时引入第三方依赖 |
| 层级选择（实现期偏差） | 原计划让"文本 prompt → 生成"在真机跑，后改为 **host 侧判 `Encode(文本) == 既有基线常量`**：该链路只有一个变量（分词），真机的数值部分已被既有用例覆盖，再搭一次双引擎不带来新信息，只消耗真机往返预算 |
| 实现期追加的前置 | 公共 JSON 解析器原本不支持 `\uXXXX`，而词表的 key 全是这种转义 → 属**实现期追加的改动面**，计划里没写 |
