## Problem

推理运行时只收发 token id：它可以做数值推理，但没有"文本进 / 文本出"的端到端路径，
文本与推理之间的那一环始终缺位。

## Goal

让框架具备"文本进 / 文本出"的路径：实现与目标模型词表一致的分词器，
并用独立参考锁定正确性。

## Scope

### Included

- 分词器实现（字节级回退语义、词表与合并规则两个数据文件）。
- **参考数据固化**：由独立实现导出 golden 文件（文本 + token id + 生成环境），
  并配来源校验（哈希）自证用例。
- 负例与边界用例。

### Excluded

- 不新增推理算子、不改运行时循环。
- 不引入运行时对第三方分词库的依赖（实现自包含）。

## Acceptance Criteria

来源：`docs/future_iterations_test_plan.md` §2.1。

1. 与独立参考**逐 token 全等**（不是"接近"——同一套确定性算法，给不出全等就说明实现有偏差）。
2. 参考数据自带来源校验，能回答"标尺有没有被改过"。
3. 覆盖边界：可选前导空格、字节级回退、特殊字符（只吃字面空格，不含制表符与换行）。
4. 缺数据文件时按既有约定：显式跳过并打印探测结果（不静默）。

## Constraints

- 数据文件放在仓库外（本地缓存），**不需要联网**；缺失时用例跳过而非失败。
- 入库的是**参考数据（标尺）**，不是大体积产物。
- 载入接口的入参语义由子类决定，不改基类签名（避免扩散到既有分词器实现）。

## 历史演进（抽取时保留）

- 立项时曾一度判定"本地没有词表数据 → 降级为需联网"；**该判断是错的**——
  当时只查了仓库目录，把"仓库里没有"当成了"机器上没有"。这条教训后来写进了证据纪律。
