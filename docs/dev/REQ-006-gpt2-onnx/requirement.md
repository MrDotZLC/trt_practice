## Problem

框架此前只有"从配置 + 权重原生建图"一条路径。外部图（ONNX）是另一条现实存在的模型来源，
它需要被纳入框架；但它的结构与原生路径不同，必须能交叉验证，否则"两条路结果一致"无法证明。

## Goal

1. **外部图路径可用**：支持动态批量/序列的 profile 设置、精度选择、失败可诊断
   （解析错误逐条打印），并能被测试与运行时复用。
2. **与原生路径交叉验证**：同一输入下两条路的 logits 按既有口径对齐。
3. **子图替换机制**：范围由当时的决策项决定（最终落实为"识别 + 断言"，见下）。

## Scope

### Included

- 外部图构建入口：profile 规则按 architecture 选择（与原生路径同一套语义）、I/O 契约校验、
  失败路径的可诊断信息。
- 图结构探针：算子分布与子图形态的识别，并对"图变了"给出可执行断言。
- 与原生路径的对拍用例。

### Excluded

- 不改文本分词、批处理、低精度量化。
- **不把外部图路径接进 Runner**——该图没有 K/V 缓存输入，做不了解码。

## Acceptance Criteria

来源：`docs/dev/REQ-006-gpt2-onnx/phase3_development_plan.md` §4（5 条，均写明验证方式）。

1. 沙箱 `ctest` 全绿（GPU 用例自动跳过）。
2. 图结构探针接入 `ctest`，且"缺环境"按设计跳过、"缺资产"判失败——两者语义分开。
3. 能对真实外部图建出可推理引擎；失败路径有可诊断信息（解析错误逐条 + I/O 名校验）。
4. 与原生路径的 logits 按判据对齐（真机相对偏差 `5.66e-07`，阈值 `1e-5`），
   并与外部参考三方对照、逐位置 argmax 一致。
5. 子图替换范围按最终决策落实：**只做识别 + 断言，不做替换**，且不靠人眼判断。

## Constraints

- 两条路必须"同名同义"：I/O 名字对不上就失败，不等到绑定时才报错。
- 缺环境 ≠ 图有问题：环境缺失可以跳过，资产缺失必须判失败（覆盖损失不允许静默）。
- 阈值必须写明出处；跨精度不可复用。
