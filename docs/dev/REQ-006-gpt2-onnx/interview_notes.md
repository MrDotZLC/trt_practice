# Interview Notes

> **性质**：历史面试口径回填（2026-10-01）。

## Project Introduction

"给框架接入第二条模型来源：外部图（ONNX）。重点是**交叉验证**——同一输入下两条路必须对齐，
否则'两条路一致'这句话没有证据。"

## Architecture Explanation

I/O 契约按模型架构分支；外部图只挂"整段前向"一组 profile；图结构探针进 ctest，成为长期护栏。

## Key Decisions

| 决策 | 选择 | 理由 |
|---|---|---|
| 子图替换范围 | **只识别 + 断言** | 实测本模型上可替换面收益为零或未量化 |
| 对齐判据 | 沿用既有实测口径，**不预先放宽** | 若偏差更大，按实测报告再定 |
| 是否支持解码 | **不支持** | 该图无 past 输入，要支持得重新导出 |

## Technical Challenges

**推翻了设计文档的预设**：原设计说"替换三类子图"，实测发现该图只有原生归一化 + 学习式位置编码，
前两类**根本没有替换对象**；第三类（注意力）在该图上也用不上（分页注意力只做解码）。
教训：**"计划里的替换对象"必须用图上的实测计数来核对**。

## Trade-offs

- 只识别不替换 → 换来零正确性风险，代价是"替换机制"这项能力没被验证。
- 不做性能结论 → 换来不写错方向，代价是"外部图快不快"这个问题留白。

## Interview Questions

### Level 1

Q：ONNX 路径做了什么？　A：解析、契约校验、profile 设置、失败可诊断，并与原生路径对拍。

### Level 2

Q：怎么知道图变了？　A：结构探针进 ctest；缺环境跳过、缺资产判红，两者语义分开。

### Level 3

Q：为什么不对齐判据预先放宽？　A：放宽阈值会掩盖真问题；要先按实测报告再定。

### Level 4

Q：为什么"替换子图"最后没做？　A：实测该图没有可替换对象（缺位置编码与归一化插件，注意力段又没有 K/V 输入）。

### Level 5

Q：性能为什么没结论？　A：两次测量方向相反、差异小于构建间噪声 → 只能写"未定"，并先建可复现测量方法。
