# Analysis

> **性质**：历史分析回填（2026-10-01）。来源：本目录 `phase3_development_plan.md` §0 / §3。

## Current Architecture

框架此前只有"从配置 + 权重原生建图"一条路径。外部图（ONNX）是另一条现实存在的模型来源，
但它当时完全没有被纳入：构建入口虽已有 ONNX 分支，却写死了 LLM 契约、没有失败诊断、也没有交叉验证。

## Data Flow

```text
ONNX 文件 → 解析器 → 网络定义 → I/O 契约校验 → profile（只挂整段前向一组）→ 引擎
原生路径  ─────────────────────────────────────────────────────────┘ 两者按同一口径对拍
```

## Relevant Modules

| 模块 | 开工时状态 |
|---|---|
| 外部图构建入口 | 有骨架；契约写死 LLM、缺失败诊断 |
| 图结构识别 | 只有一次性统计，未固化成可复现探针 |
| 与原生路径对拍 | 不存在 |

## Existing Limitations

1. 外部图不可用（契约校验过严、错误不可诊断）。
2. 没有"图变了要知道"的护栏——模型或导出路径一改，既有结论会静默失效。
3. 两条路径无法对拍 → "实现是否对齐"无从证明。

## Extension Points

- **I/O 契约按 architecture 分支**：两条路径共用同一份契约常量的基础。
- **图结构探针**：进 ctest 后成为"图变了立刻知道"的长期护栏。
- **子图识别**：真要做替换时的入口（后续由独立条目承接）。
