# Design

> **性质**：历史设计回填（2026-10-01）。从 `docs/dev/REQ-006-gpt2-onnx/phase3_development_plan.md` §0.2 / §2 决策 /

## Overview

把外部图（ONNX）纳入框架，并与原生路径交叉验证。

## Architecture

```text
外部图 ──(解析)──→ 网络定义 ──(契约校验：输入名 / 输出名)──→ profile（只挂前向一组）──→ 引擎
原生路径 ────────────────────────────────────────────────────┘  两者按同一口径对拍
```

## Module Design

| 任务 | 做什么 | 依赖 |
|---|---|---|
| P3-0 | 把算子统计固化成可复现探针（"图变了要知道"） | 无 |
| P3-1 | 外部图构建入口落地：动态 profile、精度、错误可诊断、输出名校验 | 无 |
| P3-2 | 与原生路径的数值对齐用例（含三方对照外部参考） | P3-1 |
| P3-3 | 子图识别与断言（替换范围由 D1 决定） | P3-1 |
| P3-4 | 性能对照：外部图 vs 原生（构架耗时 / 前向延迟） | P3-1 |
| P3-5 | 文档收口 | 全部 |

## Data Structure

- I/O 契约按 architecture 分支：LLM 侧输入 `input_ids`、输出 `logits`。
- 子图名白名单：注意力 / 归一化 / 位置编码——**名字写错即失败**，不允许"声明了却没核对"。

## Runtime Flow

```text
读配置 → 存在性检查 → 声明子图名校验 → 解析外部图 → I/O 契约校验
   → 挂 profile（只挂前向一组）→ 构建 → 序列化 + 指纹落盘
```

## Resource Lifecycle

- 引擎缓存指纹包含**外部图文件身份**：重新导出过图必须重建。
- 探针（图结构识别）进 ctest；缺环境返回跳过码，**缺资产判失败**——两者语义分开。

## Performance Consideration

- 当时**没有**可复现的性能结论：两次测量方向相反，差异小于构建间噪声 → 记为未定，
  后续交给独立条目做跨构建对照。
- 单点测量支撑结论的教训在本阶段被记录，并写进了测试计划。

## Trade-off

### D1 子图替换做到什么程度

| 选项 | 说明 | 取舍 |
|---|---|---|
| A 完全不做替换 | 最快 | 丢掉"验证替换机制"这一能力 |
| **C 识别 + 统计 + 断言（采用）** | 把模式识别出来并固化成 host 用例 | 无正确性收益、性能收益未量化，但能力保留且成本低 |
| B 真做替换 | 机制价值真实 | 本模型上**可替换面无收益**：图里没有旋转位置编码与归一化插件；归一化用原生层已足够；注意力虽可换但该图没有 K/V 缓存 |

**关键事实（决定了 D1）**：设计文档原写"替换三类子图"，实测该图**不含**其中两类；
可替换对象的收益要么为零、要么未量化。

### 其它决策

| 编号 | 决策 | 选择与理由 |
|---|---|---|
| D2 | 对齐判据 | 沿用上一阶段的实测口径；若算子分解不同导致差异更大，**按实测报告再定，不预先放宽** |
| D3 | 外部图是否支持解码 | **不支持**：该图是整段前向、无 past 输入；要支持需重新导出带缓存的图，与"复用现有图"的初衷相悖 |
| D4 | profile 与精度 | **复用既有能力**，不另起一套；参照历史工程校验一遍，避免重踩已解决的坑 |

## 现有资产与"为什么对齐判据是干净的"（原 PH3-ASSETS）

外部图资产：opset 17，输入为两维皆动态的 token 序列，输出为 logits
（**无 past / K-V 输入输出**，即整段前向）。

实测算子分布（2411 个节点 / 149 个初始化器）：归一化 25 处、MatMul 25 处、Softmax 12 处、
Gemm 48 处、Transpose 48 处、Gather 172 处——**没有旋转位置编码、也没有归一化插件的待替换对象**。

关键事实：图里的初始化器命名带上一层前缀，**与原生路径用的权重文件逐比特一致**
（已抽样核对 4 个张量，最大差 `0.0`），且两者用同一套输入输出约定。

→ **两条路用的是同一份数值，因此"两者输出对齐"是一个干净的判据**：不需要外部基线，
任何不一致都指向实现差异。
