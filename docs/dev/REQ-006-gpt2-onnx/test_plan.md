# Test Plan

> **性质**：历史用例回填（2026-10-01）。来源：`docs/dev/REQ-006-gpt2-onnx/phase3_test_plan.md` §2/§3/§4/§7。
> **判据以 `requirement.md` 为准**。

## Unit Test

**图结构探针**（沙箱 / ctest）：算子分布与子图形态识别 + 与基线比对；
同时带"缺失算子"护栏——一旦出现不该出现的算子，说明模型或导出路径变了，必须重审结论。

## Integration Test

| 层 | 内容 | 环境 |
|---|---|---|
| L1 | 外部图能建出可推理引擎；失败路径可诊断（解析错误逐条 + I/O 名校验） | 真机 |
| L2 | 与原生路径的 logits 对齐；与外部参考三方对照；逐位置 argmax 一致 | 真机 |
| L3 | 性能对照（外部图 vs 原生） | 真机 |

## Regression Test

- 图探针进 ctest 后，"图变了"不再依赖人记得跑。
- 沙箱全量保持全绿（GPU 用例自动跳过）。

## Failure Test

- 输入名 / 输出名对不上 → 建构失败并给出逐条错误。
- 声明的子图名不在白名单 → 失败（**名字写错即失败**）。
- 缺环境（解析库 / 资产）→ 按设计返回跳过码；**缺资产在闸门开启时判失败**。

## Expected Result

外部图可建可推理；与原生路径对齐；替换按 D1=C 只做识别与断言。

## Actual Result

全部达成（真机相对偏差 `5.66e-07`，阈值 `1e-5`）；两个缺口转开放项
（子图识别只到计数、性能测量方法缺失）。

## Status

已交付（历史条目）。
