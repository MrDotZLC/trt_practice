# Design

> **性质**：历史设计回填（2026-10-01）。从 `docs/dev/REQ-005-diagnostics-fix/phase2_supplement_plan.md` §2 任务分解抽取，
> **未新增当时的决定**。

## Overview

两个修复：① 诊断输出**不得**无条件进入网络 I/O 契约；② 环境不可用与功能失败必须分开表达。

## Architecture

```text
构建配置（已有统一入口）──→ 构建选项 ──→ 建图：诊断输出按开关决定是否标记
                                            ↓ 默认关 → 契约与修复前一致
测试侧：诊断用例走**独立引擎路径**，与生产路径的引擎缓存互不干扰
CUDA 环境判定：把"无设备"从静默跳过改为显式判定
```

## Module Design

| 任务 | 做什么 | 为什么这样做 |
|---|---|---|
| P2S-1 | 构建选项增加诊断开关（默认关），透传到建图；建图侧 4 处输出标记改为按开关条件挂载 | 所有构建期参数都已统一走"配置 → 构建选项"路径；另加默认参数会继续膨胀已冻结的入口签名 |
| P2S-2 | 诊断仪器改为显式 opt-in，并换**独立引擎路径** | 两条路共用引擎缓存会互相判过期、来回重建 |
| P2S-3 | CUDA 环境显式判定 | 消除"假绿滑梯"：环境缺失可以跳过，功能失败必须判红 |
| P2S-4 | 真机回归验证（6 条先前红 + 3 条对照） | 同时验证"开关默认关闭"与"Runner 路径恢复" |
| P2S-5 | 文档收口 | — |
| P2S-6 | 修复缓存追加用例与"整步只推一次长度"契约不同步 | 测试与产品契约必须对齐，否则红的是测试不是产品 |

## Data Structure

- 诊断开关：构建配置 → 构建选项 → 建图三层的同一个布尔值，**默认 false**。

## Runtime Flow

```text
默认路径：建网（输出数不变）→ 引擎 → 与修复前契约一致
诊断路径：开关打开 → 多 4 个中途输出 → 消费方逐个绑定 → 打印读数
```

## Resource Lifecycle

- 诊断输出是**契约变更**：多出来的每个输出，消费方都必须绑定；
  因此它默认关，只在诊断用例里显式打开。
- 两条路径的引擎缓存**独立命名**，避免互相判过期。

## Performance Consideration

不涉及性能；代价是诊断路径需要独立建一次引擎（分钟级，仅在诊断时发生）。

## Trade-off

| 决策 | 选择 | 为什么 |
|---|---|---|
| 诊断输出的默认值 | **关** | 默认打开等于把"要不要多 4 个输出"推给每个调用方 |
| 是否顺手修 FP16 NaN | **不修** | 属另一条独立路径，混进来会让归因不清 |
| 是否引入引擎缓存失效机制 | **不引入** | 本轮只用"换独立路径"绕开；根治属测试基建改造 |
