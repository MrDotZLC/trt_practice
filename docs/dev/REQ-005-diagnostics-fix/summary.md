# Project Summary

> **性质**：历史交付总结回填（2026-10-01）。来源：本目录 `phase2_supplement_plan.md` §8 执行结果。

## Problem

① 为定位数值问题挂上的诊断输出**无条件进入网络 I/O 契约**，消费方按名绑定、没人绑它们 →
真机多条用例直接失败；② 沙箱内 CUDA 不可用时"建构建器失败"被表现为**跳过**而不是失败。

## Solution

把诊断输出改回**显式开关、默认关闭**并走独立引擎路径；把"环境不可用"与"功能失败"分开表达。

## Architecture

```text
构建配置 → 构建选项 → 建图：诊断输出按开关决定是否标记（默认关）
诊断用例 → 独立引擎路径（与生产缓存互不干扰）
CUDA 环境判定：无设备 → 显式跳过并打印原因；功能失败 → 判红
```

## Implementation

开关接入（配置 → 选项 → 建图三处一起）、仪器改 opt-in、环境显式判定、真机回归验证（6 条先前红 +
3 条对照）、文档收口，并顺带修掉一处"缓存追加用例与契约不同步"的测试问题。

## Performance

**不适用**（无性能改动；默认关闭意味着生产路径零额外开销）。

## Limitation

- **不修 FP16 NaN 本身**（那是独立条目）。
- **不引入引擎缓存的失效机制**：本轮只用"换独立路径"绕开，根治属测试基建改造。

## Future Work

FP16 端到端 → `docs/dev/REQ-018-gpt2-fp16-nan/`；引擎缓存代次机制此后由指纹承担。
