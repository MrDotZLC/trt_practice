## Problem

上一阶段收尾时留了两个问题：① 为定位数值问题而挂的诊断输出**无条件进入网络 I/O 契约**，
消费方按名绑定、没人绑它们 → 真机多条用例直接失败（enqueue 报错，且报的是那个诊断张量的名字）；
② 沙箱内 CUDA 不可用时，"建构建器失败"被表现为**跳过**而不是失败，形成"假绿滑梯"——
看起来全绿，实际什么都没验。

## Goal

1. 把诊断输出改回**显式开关、默认关闭**，并让它走独立的引擎路径，避免污染生产契约。
2. 把"环境不可用"与"功能失败"分开：环境缺失可以跳过，功能失败必须判红。

## Scope

### Included

- 诊断输出开关的代码面与默认值。
- 诊断仪器改为显式 opt-in，并换用独立的引擎缓存路径。
- CUDA 环境的显式判定。
- 真机回归验证与文档收口。

### Excluded

- **不修 FP16 NaN 本身**（那是另一条独立路径）。
- **不改**单引擎切面的语义，不动注意力 / 采样器 / K-V 缓存。
- **不引入**引擎缓存的失效机制（本轮只用"换独立路径"绕开；根治属测试基建改造）。
- **不把** GPU 用例的跳过整体改成失败（会破坏"沙箱必须可绿"的既有要求）。

## Acceptance Criteria

来源：`docs/phase2_supplement_plan.md` §4（A1–A6，每条都带出处）。

1. 默认构建的网络输出数不变；单引擎切面仍为原值。
2. 打开开关的仪器路径能列出 4 个诊断输出。
3. 真机 9 条用例**全绿**（6 条先前红 + 3 条对照）。
4. FP16 复现器回到"token 全 0"的**按设计红**，而不再是 enqueue 失败。
5. 沙箱 `ctest` 仍 0 失败，且 GPU 跳过条目打印显式探测原因。
6. 沙箱内"建构建器失败"表现为 FAIL，而不是 skip。

## Constraints

- 诊断输出**不是调试开关而是 I/O 契约开关**：多出来的输出，每个消费方都必须绑定。
- 修改必须保持"沙箱可绿、真机可复现"两条同时成立。
