## Problem

语言模型的弱类型 FP16 引擎在端到端生成时结果错误：**prefill 末行 logits 全部是 NaN**，
贪心采样恒返回 0（用 `>` 比较，NaN 恒假 → 下标停在 0），生成结果不可用。

关键事实（均已实测，出处见 `docs/TROUBLESHOOTING.md` + TS-018.1）：

1. 出现 NaN 的**层随构建变化**（实测出现过第 0 / 1 / 2 层）；
2. 张量幅值**远未触及 FP16 上限 65504**（实测全在几十以内）→ 不是简单的范围溢出；
3. 同一份权重、同一个构建器，**FP32 端到端完全正确**（8/8 token 命中，logits 相对偏差约 1e-6）；
4. 曾记"已否证"：LayerNorm 计算精度、MLP 前半段（`c_fc` / GELU）、注意力输出、残差膨胀。
   **其中前两条的否证依据已被判定为不牢**（"位置不变"是 no-op 的特征；`c_fc` / GELU 与残差读数来自
   不同构建）→ 改记"待复核"，见 `analysis.md` 的 `### 已经否证的方向（复核状态）`。

**影响**：语言模型的默认构建精度就是 FP16，但推荐精度被迫改为 FP32——
"默认路径不可用"本身是一个产品缺陷，而不只是性能问题。

## Goal

定位到造成 NaN 的**具体算子**，并做最小修复，使语言模型的 FP16 端到端生成结果与 FP32 基线一致；
或在不改动产品代码的前提下，给出**可复核的结论**说明它无法在当前 TensorRT 版本上修复。

## Scope

### Included

- 复现：可运行的失败用例 + 完整的环境与输入记录（B0）。
- 诊断：把"哪一层哪个算子最先产生非有限值"钉死（B1）。
- 修复：在**最小改动**前提下的修复，且不改变 FP32 路径行为（B2）。
- 回归：原问题消失、既有功能不回归（B3）。

### Excluded

- 借机重构构建器或调整网络结构（Bugfix 禁止顺手重构）。
- 为提升 FP16 性能而做的优化（本机无 Tensor Core，收益有限——那是另一件事）。
- 激活缩放 / 量化感知等"新功能"级方案（若需要，走 Bugfix → Feature Decision）。

## Acceptance Criteria

1. **原问题消失**：FP16 端到端用例（当前按设计红）转绿，且输出与 FP32 基线逐 token 一致。
2. **不回归**：FP32 / INT8 路径与全部现有用例不出现新红；沙箱全绿。
3. **可解释**：能说清"是哪个算子在 FP16 下产生非有限值、为什么"，而不是"改了几处就好了"。
4. **判据有出处**：新增 / 修改的任何数值阈值都要写明来源（`AGENTS.md` §7）。

## Constraints

- **策略前提（2026-10-06 已裁决：撤销"按政策不修"）**：撤销由作者裁决，理由口径 = **正确性**
  （默认构建精度不可用即产品缺陷），与 `PROGRESS.md` §5.11 / `future_iterations.md` §1.4 的旧口径
  （**性能收益有限** → 不急）**不是同一个判据**——旧的收益结论本身未被推翻，只是不再作为本条的策略前提；
  旧结论的载体（§5.11 / TS-018.1 / §1.4）同步改成指针，不复述条文。
- **改动预算**：Bugfix 默认"文件 ≤ 3 / 行数 ≤ 100"；超限必须停下来做决策，禁止自动升级为 Feature。
- **设备前提（2026-10-06）**：当前设备**无编译与真机条件** → 诊断（B1'）、修复验证（B2）、
  回归（B3）与依赖头文件的核实（评审 P0-3）**一并搁置**，等真机窗口；本次只落"待执行"的方案与判据，
  不得把任何未跑过的读数写成通过。
- 复现与验证只能在真机完成（沙箱无 GPU），每次往返都需要批准。
- 目标硬件无 Tensor Core：修复的价值是"默认路径正确"，不是"FP16 更快"。
