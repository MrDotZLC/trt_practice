## Current Architecture

复现路径上的结构：

```text
权重（FP32 源）→ 语言模型原生建图（常量按"整网倾向精度"建）
      ↓
两层引擎：prefill（整段前向，导出每层 K/V）/ decode（单 token，读分页 cache）
      ↓
运行时：查询引擎声明的边界精度 → 分配缓冲 → 采样
      ↓
诊断仪器：第 0 层的 4 个中途张量（可选导出）+ 逐层 K/V 扫描
```

关键结构事实：

- 弱类型网络：是否用 FP16 由 TensorRT 按 flag 与 tactic 决定，**图层没有强制逐算子类型**。
- 归一化层已经显式设成 FP32 计算精度（这是上一轮定位的产物，已被证明不是根因但保留）。
- 诊断输出是一个**开关**（默认关），打开会改变网络的 I/O 契约——这本身也曾造成过真机 6 条红
  （`docs/TROUBLESHOOTING.md` + TS-019）。

## Module Structure

| 模块 | 与本题的关系 |
|---|---|
| 语言模型构建器 | 建图处；中间张量的导出点都在这里 |
| 构建配置 | 精度档位与诊断开关 |
| 运行时 | 按引擎声明的精度分配缓冲；FP16 下 K/V 与 logits 的声明精度与配置不同（已固化处理） |
| 诊断用例 | 打印各输出是否 NaN、逐层 K/V 的幅值 |
| 复现用例 | FP16 贪心 8 token 与参考对比（当前按设计红） |

## Data Flow

诊断数据流（当前只覆盖第 0 层）：

```text
prompt → prefill 前向
   ├─ 每层 K/V 输出 → 逐层扫 NaN/Inf（能定位"从第几层开始"）
   └─ 第 0 层中途张量（注意力残差 / MLP 残差 / c_fc / GELU）→ 判断 MLP 还是注意力
      ↓
末行 logits 统计（max / mean / 是否 NaN）
```

## Runtime Flow

- 每次真机诊断需要：重建 FP16 引擎（分钟级）→ 跑一次 prefill → 读回诊断张量 → 人工比对。
- 引擎缓存按构建指纹复用；改图 / 改开关会触发重建（属预期）。

## Existing Limitation

### 已经否证的方向（**其中两条的依据已被判定为不牢，见"复核状态"列**）

> 本表的用途是"别重复走已走过的路"，**不是"不许复核"**。2026-10-06 的评审（`review.md` P1-2 与
> 设计 v2 的 D1）判定：下表有两条的**依据本身不成立或不足**，所以它们从"已否证"降为"待复核"——
> 这正是 AGENTS.md §5 第 4 条要求的反向检查（文档与证据矛盾必须当场修，并连原因一起写）。

| 方向 | 原否证依据 | 复核状态 |
|---|---|---|
| LayerNorm 计算精度 | 显式设 FP32 后 NaN 依旧、位置不变 | **依据不成立**："位置不变"同样是 no-op 的特征（真换了计算路径通常会挪动首 NaN 层）。降为待复核，判别动作 = 读引擎逐层精度（v2 的读数 ② / ④）确认那 3 个 Normalization 层是否真是 FP32 |
| MLP 前半段（`c_fc` / GELU） | 两个切点都干净，而同一层的残差输出是 NaN | **依据不足**：这两个读数来自**不同构建**（第 4 轮量 `c_fc` / GELU，第 3 轮量残差），从未在同一次构建的同一层上同时成立。降为待复核，由 v2 的三图对照在同一次构建内给读数 |
| 注意力输出 | 第 0 层注意力残差干净 | 维持有效 |
| 残差膨胀到 FP16 溢出 | 幅值全在几十以内，距 65504 差几个数量级 | 维持有效（注意：**平方和**的溢出线是 2^12 量级，与"距 65504 差几个数量级"不是同一把尺子，见 D1 的 H1） |
| "NaN 层在漂移" | 是**观测缺口**：中途张量只导出了第 0 层，看不到后面 | 维持有效，且 2026-10-06 追加一条：前 5 轮**每轮都在改图**，漂移里还可能含"仪器换了"的成分（`TROUBLESHOOTING.md` 18.2 的教训 1） |

### 尚未回答的问题

1. **最早出现非有限值的确切位置**：现有仪器只能给"第几层的 K/V"，给不出"层内哪个算子"。
2. **是否与 tactic 选择相关**：同事不同构建下 NaN 层不同，指向"某个算子在 FP16 下的数值行为
   随 tactic 变化"。本机（WSL2）拿不到 kernel 级时间线，但**图层级的 tactic 信息可读**
   （引擎检查器），这条路还没走过。
3. **是否是"具体算子的输入极端值"**：幅值整体不大，但**局部最大值**没有被记录过
   （现在只记了 K/V 的 max|v| 与前 3 层的幅值）。
4. **FP16 引擎里哪些张量真的以 FP16 执行**：弱类型网络下这是 TRT 决定的，属于**可查询**的事实，
   但从未被系统记录过（只在边界张量上查过）。

### 已知的观测陷阱（写下来避免重蹈）

- **仪器覆盖不足时不要把"观测缺口"当成现象**（TS-018.1 的方法教训 1）。
- **每轮只改一个变量**（TS-018.1 的方法教训 2）——同时加两个切点会分不清归因。

## Extension Point

- **诊断面扩展**：把中途张量的导出从"只有第 0 层"扩到全部层（或按需的前 N 层），
  是回答"最早在哪一层哪个算子"的最短路径。改动集中在构建器的导出点。
- **精度事实的读取**：引擎检查器能读出**逐层**的实际计算精度与 tactic 选择，
  这是当前唯一不需要 GPU 时间线就能拿到的"算子在 FP16 下怎么执行"的事实来源。
- **二分手段**：对可疑算子显式设计算精度，是"逐算子二分"的现成手段（归一化上已经用过一次）。

依 `phases/p1_analysis.md` 的术语表规则：`requirement.md` 里的每个模糊名词在此给出**可验证定义**——

| 名词 | 可验证定义（怎样算做到 / 没做到） |
|---|---|
| **具体算子** | 能指名到建图 API 的那一层（如 `c_proj` 的 MatMul、bias 的 `kSUM`、`addSoftMax` 的 `ISoftMaxLayer`）。判据 = **该算子的输入全部有限、输出出现非有限值**；只说到"第 N 层"不算做到。 |
| **最小修复 / 最小改动** | 改动只落在"钉死的那一类算子"的精度设置或绑定修正上；文件 ≤3、行数 ≤100；**且 FP32 路径的数值行为不变**（FP32 建图产物与逐 token 输出不变）。 |
| **可复核的结论** | 必须同时给出"算子 + 机制 + 判别量"三件，且判别量能在**同一构建**上重放（附构建指纹 / tactic 名单）。只有现象、没有机制的不算。 |
| **与 FP32 基线一致** | 同一份权重、同一 prompt、同一采样配置下，FP16 生成的 token 序列与 FP32 **逐 token 相同**（长度 = 用例内声明的 token 数）。不引入新的数值阈值。 |
| **不回归（无新红）** | 真机全量用例的**失败集合不新增成员**；沙箱侧以最新实测基数为准（当前 268，新注册 host 用例后应为 269，**待复跑**）。红名单里只允许"按设计红"。 |
| **非有限值** | `isnan(v) || isinf(v)`（NaN 与 Inf 同级）。判据是"该张量内**是否存在**"；定位用的是"逐层 / 逐切点里**第一个**存在的"。 |

### Architecture

架构不改动，只加"观测面"与"对照臂"：

```text
prefill 前向（同一份权重、同一个 prompt）
   ├─ 图 A：生产图（不加任何输出）+ detailed_profiling
   │     → ① 逐层 K/V 的首个非有限层 L_A（含 max|v| / RMS）
   │     → ② 逐层 ONELINE（层类型 / 计算精度 / TacticName）
   ├─ 图 B：全探针图（12 层 × 7 切点）+ detailed_profiling
   │     → ③ 层内首个非有限张量
   │     → ④ 同 ② 的 tactic 名单（用于与图 A 对照）
   └─ 图 C：FP32 同探针图（对照臂）
         → ⑤ 健康幅值剖面（每层 LN 输入的 max|v| / RMS）
         → ⑥ 仪器自证：C 必须全有限，否则仪器本身有 bug
```

7 切点（逐层）= `attn_ctx_{L}`（注意力输出，c_proj 前）/ `attn_out_{L}`（c_proj 后）/
`attn_res_{L}`（注意力残差后）/ `ln2_out_{L}` / `mlp_fc_{L}` / `mlp_gelu_{L}` / `mlp_res_{L}`。
另加**只有一份**的 `block_in_0`：第 L≥1 层的 block 输入与上一层的 `mlp_res_{L-1}` 是**同一个张量**，
而一个张量只能有一个名字 / 一次输出——所以逐层探针是 12 × 7 = 84 个，加 `block_in_0` 共 **85 个**。

| Module | Responsibility | Dependency |
|---|---|---|

| tactic / 精度读数 | `IEngineInspector` 逐层 ONELINE 落盘，提取 `TacticName` | `detailed_profiling=true`（`src/core/builder.cpp:254`）；读法复用 `test_resnet18_int8_probe.cpp` 的 `InspectTactics` |

### Data Structure

```text
LayerProbe {                  // 每条 = 一次诊断读数
    int32_t layer;
    const char* tensor;              // block_in / attn_out / attn_res / ln2_out / c_fc / gelu / mlp_res
    bool has_non_finite;
    int32_t first_non_finite_index;  // 区分"整行坏"与"某个位置坏"
    float max_abs;
    float rms;
}
```

三条口径：

1. **必须同时记"是否非有限"与幅值**——只看前者分不清"突变"与"逐步膨胀"。
2. 新增**首个非有限下标**与 **RMS**：只记 max 看不出"整行坏"还是"个别位置坏"，
   而 H1（行内归约）的判别量正是 **LN 输入的 RMS**。
3. **输入按声明 dtype 填、输出遇未识别名字即失败**（落码期口径，2026-10-06 定）：
   今天测试的 `seq * 768` 兜底会让新探针名安静地分配过小 → 越界写 → 假 NaN，所以先把兜底换成硬闸；
   完整版"尺寸与形状全部从引擎读"依赖 `getTensorShape` 对**动态维**的语义，而本机无 TRT 头文件、
   无法建引擎证实 → 记为**待真机项**，不猜语义。
   `padding_bias` 按声明形状 `[B,1,1,S]` **全写 0**，且 S 维必须与 `input_ids` 的 S 一致——
   `llm_runner.cpp:461-493` 已记着"两个输入的动态维不会自动绑定"这条坑。
   今天诊断用例在这一路上**没有自证**（给 rank-2 形状、写进 position id 的位型）：
   FP16 下那些次正规数恰好下溢成 0，**图 C 是 FP32，会真的加进注意力分数**——所以跑图 C 前必须先修。

### Runtime Flow

```text
一次真机窗口
  图 A（生产图，无额外输出） → ① L_A 与逐层幅值；② 逐层 tactic / 精度
  图 B（全探针图）          → ③ 层内首个非有限张量；④ 逐层 tactic / 精度
  图 C（FP32 同探针图）     → ⑤ 每层 LN 输入的幅值剖面；⑥ 仪器自证（必须全有限）
        ↓
判定 1：L_A 与 L_B 是否相等
  ├─ 相等 → 仪器未扰动被测对象，③ 可用（进判定 2）
  └─ 不等 → 观测效应成立：② / ④ 的 tactic 指纹成为本次读数的上下文，
            并**在图 B 上按层二分**（每层单独建一份探针图，逐层排除）
            —— 这就是 v1 的"逐算子二分"路线，降级为兜底
        ↓
判定 2：③ 定位到的张量落在哪一族
  ├─ LN 族（`addNormalizationV2`）→ 出口 A
  ├─ Softmax 族（`addSoftMax`）   → 出口 A'（先核实接口）
  └─ 绑定 / 精度契约             → 出口 B
        ↓
出口 A / A' / B 落地 → 重建 → 复跑
        ↓
非有限值消失 且 与 FP32 逐 token 一致 → 进 B3
```

**代价上限（评审 P0-2 的关闭项）**：一个真机窗口内最多 **1 次全导 + 3 次切层二分**
（共 4 份 FP16 探针图）。超过仍未定位到"具体算子"（Terminology 第 1 条）→ 按出口 C 出结论：
"只到层、不到算子"，并把 ② / ④ 的 tactic 指纹一并写进结论。
**不做无限二分**：真机往返是这条目里最稀缺的资源。

### Resource Lifecycle

| 资源 | 变化 |
|---|---|
| 诊断输出缓冲 | 每次诊断按需分配、用完释放；**不进产品路径**（默认关） |
| 探针引擎 | 路径独立（`/tmp/..._probe.engine`），**用完即弃**；开 / 关诊断的指纹不同 |
| **探针集合的变化** | **必须 bump 图版本（或把探针集合并入指纹）**——否则改了探针集仍会复用旧引擎，读回来的还是上一次仪器的读数（`TROUBLESHOOTING.md` TS-040 同类） |
| 运行时缓冲 | 不变 |
| 图 C 的 `padding_bias` | **全 0**（FP32 下不是 no-op，见 Data Structure 第 3 条） |

### Performance Consideration

- 本题**不追求性能**。修复的目标是"默认精度可用"。
- 若最终方案是"部分算子保 FP32"，代价是每层多几次类型转换，**必须如实报告**，
  且不能声称"没有代价"；对照必须用**同一次构建的引擎**（`PROGRESS.md` §6.4：重建 ≠ 逐字节相同）。
- 本机无 Tensor Core：即使修好 FP16，收益也主要是"显存减半 / 带宽减半"，
  性能对照要按带宽口径讲，不要按算力口径讲。
- 图 B 的 85 个探针输出（12 层 × 7 切点 + `block_in_0`）只存在于**诊断引擎**，不进产品路径；
  引擎体积与构建时间是这次刻意付出的代价（换"读数可比"）。

### Trade-off

#### D1 假设与判别量

| # | 假设 | 判别量 | 支持 / 否证线 | 现状 |
|---|---|---|---|---|
| H1 | 行内归约在 FP16 下溢出 / 塌陷（LN 的均值方差、Softmax 分母） | 首个 NaN 层 **LN 输入的 RMS** | 768 维平方和溢出点 = `sqrt(65504 / 768) ≈ 9.3`；一次和溢出点 = `65504 / 768 ≈ 85.3`（推导：FP16 上限 65504 ÷ hidden 768）。实测出现过 95.4 的 max\|v\| → **已在射程内**，不是"差几个数量级" | **部分已否证但证据不牢**：`setComputePrecision(kFLOAT)` 已在 `gpt2_model_builder.cpp:256`；但"位置不变 ⇒ 排除"被评审判为不牢（no-op 也是位置不变）。判别动作 = 读 ② / ④ 确认那 3 个 Normalization 层是否真是 FP32 |
| H2 | tactic 相关（弱类型 FP16 下选到有数值缺陷的 kernel） | `L_A` vs `L_B` + ② / ④ 的 tactic 名单 | 同图同 tactic 仍复现 ⇒ 排除；图一变、层就变 ⇒ 成立 | 待真机 |
| H3 | 层内局部极值从没被量过 | ⑤ 每层 LN 输入的幅值剖面 | 纯测量，给 H1 供输入；顺带验"幅值全在几十以内"对**层内**张量是否也成立 | 待真机 |
| H4 | 非数值路径：FP16 引擎 I/O 的声明精度与 runner 分配不一致 | 声明精度表 ↔ 分配表逐行对账；logits / K-V 首 16 个元素原文 | 零真机成本可先做；NaN 落在正常区域且 FP32 同路径干净 ⇒ 排除 | **已做静态半边（2026-10-06）：主路径排除**，只留一条更窄的待真机项 → **D1a** |

#### D1a H4 对账结果（2026-10-06，静态半边，零真机成本）

对账对象：构建器声明的 I/O ↔ `LLMRunner` 的缓冲分配（逐项，来源 = 代码行）。

| 张量 | 构建器侧声明 | runner 侧分配 | 一致 |
|---|---|---|---|
| `input_ids` / `position_ids` | `kINT32`（`gpt2_model_builder.cpp:548-553`） | `batch * seq * sizeof(int32_t)`（`llm_runner.cpp:339-340`） | ✅ |
| `padding_bias` | `kFLOAT` `[B,1,1,S]`（`:572`） | `batch * seq * sizeof(float)`（`:341`），填 0 / `-1e4`（`:469-480`） | ✅ |
| `logits` | markOutput 后**由 TRT 决定**（`:1109-1110`） | 查询声明精度后按 `elem` 分配（`:294`、`:342-344`） | ✅ |
| `k_layer{i}` / `v_layer{i}` | 同上（`:1058-1059`） | 查询**第 0 层**后按 `prefill_kv_elem` 分配（`:292`、`:318`） | ⚠️ 见下 |
| decode `key_cache_0` | 由引擎决定 | 与 `Config::is_half` **不等即拒绝启动**（`:115-121`） | ✅ |
| PagedKVCache | — | `is_half = config_.is_half`；`source_is_half = prefill_kv_half_`（查询值），由写入内核做源→目标转换（`:173-174`） | ✅ |

**结论 1（排除）**：主路径**没有**按 `Config::is_half` 硬编码宽度的地方——凡是"TRT 决定"的张量，
runner 都先查询再分配，且 decode cache 与 prefill/decode K/V 的不一致都做了拒绝启动。
所以"FP16 引擎的 I/O 声明精度与 runner 分配不一致"这一条**在产物路径上不成立**
（`TROUBLESHOOTING.md` TS-018 前半段那类越界写今天不会再复现）。H4 从"嫌疑"降为"仅剩一条窄假设"。

**结论 2（留下的待真机项，一行断言的成本）**：`dtype_of` 只查了 `k_layer0`，其余 11 层的 K/V
声明精度**假定与之相同**（`:129-132`）；decode 侧同理只查 `key_cache_0`。若某一层与第 0 层不同，
那一层的缓冲就会按错误宽度读写——正是 #18 的形态且**不报错**。
判据：真机逐层打印 `getTensorDataType("k_layer{i}")`（prefill 与 decode 各 12 层）+
`key_cache{i}`，要求**全层一致**；不一致即本假设成立、按出口 B 处置。

**结论 3（仪器侧，非产品）**：唯一确实写错的是**诊断用例**——`padding_bias` 被写进 position id 的
位型、形状按 rank-2 设、张量体积按名字猜（`tests/test_gpt2_generate.cpp` 的
`Gpt2GenerateTest.Fp16PrefillOutputsDiagnostic`，绑定循环从该文件第 470 行附近的输入分支开始）。
FP16 下那些次正规数恰好下溢成 0，所以它掩盖至今；**FP32 对照臂（图 C）会被它污染**。
这条已写进 `### Data Structure` 第 3 条，是 B1' 必须先修的仪器项。

#### D2 修复出口

| 出口 | 触发 | 动作 | 判据来源 | 预算 |
|---|---|---|---|---|
| **A** | H1 成立且目标是 **LN 族**（`addNormalizationV2`） | 把该族的计算精度显式设 FP32 | **有先例**：`gpt2_model_builder.cpp:256` 的 `setComputePrecision(kFLOAT)`，而 TRT 头文件对该接口的说明正是"避免混合精度下的溢出" | ≤1 文件 / ≤30 行 |
| **A'** | H1 成立且目标是 **Softmax 族** | 先核实 `ISoftMaxLayer` 在 TRT 10 是否有等价的"计算精度"接口；有则设精度，无则改"显式 Cast 子图"，再不济按出口 C | **来源缺失（评审 P0-3）**：`addSoftMax`（`gpt2_model_builder.cpp:948`）今天没有精度设置，而本机无 `NvInfer.h`，**查不到** → 必须由真机读头文件或建最小图核实 | 核实前不给预算；有接口 ≤30 行，无接口另算 |
| **B** | H4 成立 | 修绑定 / 契约（按声明精度读、按声明形状填） | 本项目 TS-018 前半段（FP16 缓冲按假定精度分配 → 越界写）的同类先例 | ≤2 文件 |
| **C** | H2 成立（TRT 侧缺陷）或需要激活缩放 | 停在 B2，写"不可在 Bugfix 预算内修复" + 可复核结论，转 Feature 的决定交作者 | — | — |

出口 A 的第二步控制：若读到 FP32 而 NaN 仍在，第二步改为「显式把该张量 Cast 到 FP32 再进归约」，
因为 `setComputePrecision` 承诺的究竟是"避免溢出"还是"覆盖归约本身"尚未核实（评审 P1-2）。

#### D3 观测扩展的方式（v1 的反转）

| 方案 | 说明 | 取舍 |
|---|---|---|
| **A. 一次全导（v2 采用）** | 图 B 一次挂 12 层 × 7 切点 | 诊断引擎大、构建慢；但**读数可比**，而且"观测效应"本身变成可判定量 |
| B. 逐轮按需导出（v1） | 只导可疑层，分批做 | 引擎小；但每轮换仪器 → 与前 5 轮同样的方法缺陷，读数之间不可比 |

理由：本仓库已实测"探针输出会改变 TRT 的融合与 tactic 选择"；在 tactic 本身就是嫌疑之一的前提下，
逐轮加探针**在方法上自相矛盾**。

#### D4 预算超限时怎么办

| 方案 | 说明 | 取舍 |
|---|---|---|
| A. 停在诊断结论 | 输出"哪一层哪个算子 + 为什么"，不改产品代码 | 成本最低、结论可复核；但默认精度仍不可用 |
| B. Bugfix → Feature Decision | 由作者决定是否立为 Feature，走完整设计流程 | 合规（技能禁止自动转换）；但要走完整流程 |

v2 之下出口 A / B 都在预算内；**只有出口 A'（无接口、需显式 Cast 子图）与出口 C 会回到这张表**。
