## Problem

1. **一次只服务一个请求。** 当前自回归推理按"批量 = 1"设计：整条解码循环、结果缓冲、K/V 登记
   都只服务一条序列。多请求只能串行排队，设备利用率低。
2. **解码是访存受限，却完全没有摊薄。** 每生成一个 token 就要把全部权重读一遍显存，而参与计算的
   只有 1 个位置的激活。批量 > 1 时同一份权重只读一次、算多行——这是这一档延迟-吞吐曲线里
   最直接的杠杆。
3. **分页 K/V 的记账能力已经具备，运行时侧却没有调度。** 请求何时进入批次、结束后何时归还
   K/V 块、批次成员在运行中如何变化，这些当前没有定义，也没有"跑完 N 轮不泄漏"的保证。

## Goal

让推理运行时能同时服务多条序列，并具备最小的请求调度能力：请求可以进入批次、在批次内各自推进、
结束后释放其 K/V 资源；批量执行的数值结果与"逐条单独执行"一致。

## Scope

### Included

- 批量 > 1 的前向路径（同一份权重、同一份 K/V 池、同一批 token 一起前向），prefill 与 decode 都要。
- 每序列独立的长度记账、位置编码推进与结果收集。
- 每序列独立的采样参数（同一批里允许各序列用不同的采样策略）。
- 每序列独立的 K/V 分页分配与回收，以及跨请求重复调用时不泄漏。
- 请求级调度：先做静态批（一批请求同进同出），再做运行中增补 / 退出的最小连续批。
- "批量运行 == 逐条单独运行"的数值一致性判据。
- 不等长批的 prefill **按各序列真实长度计费**（不因同伴更长而多算）；两条实现路径都要交付——
  **打包路径为默认**，"填充 + 掩码"路径保留为对照 / 回退。
- **长 prompt 的分块推进**（里程碑 S5，2026-10-04 立项）：一条序列的 prompt 允许跨多步分批送进前向，
  用来压住"长 prompt 独占一步"造成的 decode 尾延迟抖动；交付判据含"分块与不分块的结果逐位相同"。

### Excluded

- 抢占与换出（显存不足时把某条序列的 K/V 换到主存，或丢弃后重算）。
- **调度层**的混批 / 分块优先级策略（例如为压尾延迟而按分块重排准入顺序）。
  说明（2026-10-04）：**执行层**的"一次前向装两相、按段分派计算路径"（里程碑 S4）与
  **分块 prefill**（里程碑 S5）都**不在排除之列**——它们已立项交付，见下方 Included。
- 多流并行、CUDA Graph 捕获。
- 服务层（HTTP / gRPC）；beam search、重复惩罚等新采样语义；温度缩放。
- **循环内同步等待** EOS（G2-4 的原始约束就是"不能在循环内同步等 EOS"；异步回读 + 步边界检查属于本轮范围）。
- 跨引擎（多模型）调度与多卡。

## Acceptance Criteria

1. **数值一致性**：同一组请求，批量运行时每条序列的每个 token 与"逐条单独运行"**完全一致**。
   逐条单跑本身就是参考实现；这条判的是"批量路径拼错了没有"，不是"接近就行"。
2. **长度不齐**：批次内各序列已生成长度不同时，位置编码与语境长度逐序列正确。
3. **资源回收**：一条序列结束后其 K/V 块被归还；连续跑 N 轮请求后空闲块数回到初始值。
4. **不回归**：现有沙箱用例全绿；真机既有用例（FP32 端到端、K/V 缓存、插件）不出现新红。
5. **单序列语义不变**：批量为 1 时行为与现状逐 token 相同。
6. **性能结论必须可复现且不自证**：吞吐 / 延迟的改动前后对比按项目既有协议执行（同 session、
   同二进制 A/B、同轮交替、报中位数与四分位），并先给出该口径的判别下限。本机判别下限约
   ±400~600 µs（`docs/PROGRESS.md` §5.13b）；小于该量级的观测只能写"无显著差异"，
   **不得**按百分比自动接受。
7. **不浪费**：不等长批的算力不随"本批最长序列"增长（同一批内长度差很大的两组输入对比，最长那条的长度
   不改变短序列的代价）；判别口径与下限在设计与测量阶段确定。
8. **两条路径各自成立且可回退**：打包路径（默认）与"填充 + 掩码"路径**各自**满足判据 1；
   两条路径的数值差异（kernel 不同 / 浮点累加顺序不同）必须写明来源与容差出处（`AGENTS.md` §7），
   **不要求**跨路径逐位相同；默认路径可切回，且切换不改调用方接口。
   **口径（2026-10-05 作者选 (a) 后限定）**：packed 路径自身多一个**声明式必需参数**（单步
   per-row 上界，见 `p5_s5_interface_spec.md` §2：未声明时**构造期显式拒绝**）。它属于 packed 路径
   的必需参数，**不是**"切换"带来的调用形状变化 —— 两条路径仍是同一套调用 API（见
   `review.md` 的第三遍复评 P1-1）。
9. **分块与不分块等价**（里程碑 S5）：同一条 prompt 无论一次送完还是切成多步推进，产生的 token
   逐位相同；分块不得改变同批其它序列的结果，也不得让 K/V 记账或块预算出现少算 / 多算。

## Constraints

- 硬件：GTX 1660 Ti（sm_75、**无 Tensor Core**）、单卡、6 GB 显存 → 可同时服务的请求数受显存与
  引擎形状上限共同约束，不能靠"调大某个参数"绕过。
- 解码循环内禁止 H2D / D2H 同步拷贝（项目既有硬约束）。
- 批上限必须落在引擎 profile 声明的范围内，否则引擎直接拒绝执行。
- 沙箱无 GPU：数值与性能验收只能在真机完成（按 `AGENTS.md` §0.3 需先获批准）。
- 判据阈值若需要新增，必须写明出处；不许用"放宽阈值"换取通过（`AGENTS.md` §7）。
