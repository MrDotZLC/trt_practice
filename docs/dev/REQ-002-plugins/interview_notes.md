# Interview Notes

> **性质**：历史面试口径回填（2026-10-01）。与项目级 `docs/interview_summary.md` 层级不同。

## Project Introduction

"框架的第二阶段：把推理必需的算子自己写出来——归一化、位置编码、分页注意力、采样器，
每个都做成'可被真实调用路径使用'的插件，而不是只在测试里手工挂载。"

## Architecture Explanation

插件基类承担样板（命名空间、公共序列化），子类只实现业务接口；创建器负责反序列化与注册。
采样器不是插件，是自由函数形式的 kernel。

## Key Decisions

| 决策 | 选择 | 理由 |
|---|---|---|
| 插件接口 | 当前推荐的接口，按能力拆分 | 旧版属 legacy |
| 动态形状 | 显式支持动态批与动态序列维 | 后续双引擎切换依赖它 |
| 显存 | 严格走工作区机制 | 执行期临时分配不可控 |
| 采样器 | 先保正确性（排序库），优化延后 | 优化要有 baseline，当时没有 |

## Technical Challenges

- **部分旋转**：位置编码只在部分维度上旋转时，尾部必须保持原值——这条用"边界用例 + 真机验证"锁住。
- **分页注意力的契约**：查询、键缓存、值缓存、块表、上下文长度，外加可选的"当前 token 的 K/V"；
  半连接（只给键不给值）必须被拒绝。

## Trade-offs

- 正确性优先、性能延后：换来"先用可核对的参考实现锚住语义"。
- 算子只做解码阶段：换来插件代码简单，代价是预填充要另走原生子图。

## Interview Questions

### Level 1

Q：这个插件是什么？　A：把某个算子的 CUDA 实现接进推理运行时，并负责形状、精度与序列化。

### Level 2

Q：为什么不用旧版插件接口？　A：当前运行时推荐按能力拆分的新接口，旧版是 legacy。

### Level 3

Q：动态形状怎么支持？　A：输出形状用表达式给出动态维，配置阶段校验形状契约。

### Level 4

Q：显存怎么管？　A：只走工作区机制，尺寸按动态形状上界给；执行期不分配。

### Level 5

Q：怎么证明算子是对的？　A：算子级单测（对 CPU 参考）+ 经真实权重加载路径的端到端用例（真机）。

## Follow-up Questions

- 采样器为什么不在插件里？（它是自由函数，插件用于网络层）
- 半精度判据是什么？（相对误差 < `1e-3` + 绝对护栏；**该阈值不跨精度复用**）
