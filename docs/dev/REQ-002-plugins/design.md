# Design

> **性质**：历史设计回填（2026-10-01）。从 `docs/dev/REQ-002-plugins/phase1_development_plan.md` §2 架构决策 /
> §4 各 Plugin 详细设计 / §5 基类完善抽取，**未新增当时的决定**。

## Overview

交付第一批量产算子：统一插件基类封装 + 三个算子插件 + 采样器 kernel，每个都要有单元测试。

## Architecture

分层：**插件基类**（公共序列化 / 命名空间等样板）→ **各算子插件**（只写业务接口）→ **创建器**
→ **注册逻辑**。采样器不走插件路径，是自由函数形式的 CUDA kernel。

## Module Design

| 模块 | 职责 | 依赖 |
|---|---|---|
| 插件基类 | 插件命名空间、公共序列化辅助；子类只实现业务接口 | 运行时插件接口 |
| 归一化插件 | 沿最后一维做归一化 | 基类 |
| 旋转位置编码插件 | 按位置对部分维度做旋转（支持部分旋转） | 基类 |
| 分页注意力插件 | **仅解码阶段**（查询序列长度 = 1），支持 MQA / GQA / MHA | 基类、显存工作区 |
| 采样器 kernel | 贪心 / Top-K / Top-P 三套实现 | 排序库 |
| 创建器与注册 | 插件名 → 创建器；避免与运行时原生层重名 | 插件实现 |

## Data Structure

- 插件属性经序列化字段显式声明（例如块大小必须显式配置，无默认值）。
- 分页注意力的输入契约：查询、键缓存、值缓存、块表、上下文长度，外加可选的"当前 token 的 K/V"。

## Runtime Flow

```text
建网：插件实例 → 配置形状与数据类型 → 声明输出形状 → 序列化
执行：绑定 → 计算工作区（按动态形状上界）→ enqueue → 输出
```

## Resource Lifecycle

- 插件实例随网络 / 引擎生命周期管理；反序列化路径必须能重建实例。
- 中间缓存**严格通过工作区机制申请**，执行期禁止临时分配显存。

## Performance Consideration

- 采样器当时以"正确性优先"为原则（整行排序），性能优化留到后续迭代。
- 分页注意力的并行维度是 `(头, 批)`；该结构后来成为长上下文优化的改造对象。

## Trade-off

| 决策 | 选择 | 为什么 |
|---|---|---|
| 插件接口版本 | **当前推荐的插件接口** | 旧版属 legacy；按能力拆分实现 |
| 动态形状 | **显式支持动态批与动态序列维** | 后续阶段的双引擎切换依赖它 |
| 显存申请方式 | **工作区机制** | 执行期临时分配不可控且违反项目约束 |
| 精度 | 默认半精度、支持单精度回退；低精度量化延后 | 目标硬件低精度收益有限 |
| 命名 | 层名加项目前缀、创建器用固定前缀 | 避免与运行时原生层重名 |

## 风险与应对（原 PH1-RISKS）

| 风险 | 影响 | 应对 |
|---|---|---|
| 插件接口细节与运行时头文件不完全一致 | 编译 / 链接失败 | 边实现边对照运行时头文件与示例 |
| 分页注意力核性能差 | 解码阶段吞吐低 | 先保正确性，后续再做 warp / block 级优化 |
| Top-K / Top-P 核复杂、易错 | 采样结果与参考不一致 | 先用排序库实现正确版本，再手写优化 |
| 沙箱无设备，无法本地验证 | 开发迭代慢 | 由作者在真机执行；或用无头剖析工具分析 |
| 旋转位置编码的位置处理 | 与外部实现对不齐 | 与参考实现逐 case 比对 |
| 验证需人工触发 | 沙箱无设备 | 任何验证 / 测试任务执行前需经人工确认 |

## 阶段级决策（原 PH1-DECISIONS 的 D1–D5）

| 编号 | 决策项 | 结论 |
|---|---|---|
| D1 | 分页注意力范围 | 只做解码阶段（GQA/MHA）；预填充计入后续迭代 |
| D2 | 采样器实现路线 | 先用排序库保正确性；手写优化 kernel 计入后续迭代 |
| D3 | 对比策略 | 算子层逐元素对比；生成层对比分布 / logits 统计量 |
| D4 | **半精度精度标准** | **相对误差 < 1e-3**，配合绝对误差护栏。**该阈值是半精度专用，不可套到其它精度上** |
| D5 | 真机验证 | 所有 CUDA / TensorRT 测试需人工确认后执行 |
