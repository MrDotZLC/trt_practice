# Analysis

> **性质**：历史分析回填（2026-10-01）。来源：本目录 `phase4_int8_plan.md` §1 技术前提 / §2 方案。

## Current Architecture

低精度量化有两条路线：**隐式校准**（需要校准器）与**显式量化节点**（Q/DQ）。前者在当前运行时
版本已废弃并指向强类型方向；后者需要自己产出量化图，且"怎么算合格"必须单独定。

## Data Flow

```text
外部参考权重 → 外部图 →（插对称 Q/DQ）→ 量化图 → 既有外部图构建入口 → 引擎
                    ↑
              产图脚本：量化尺度在这里算并写进图
```

## Relevant Modules

| 模块 | 开工时状态 |
|---|---|
| 产图工具链 | 只有针对该模型的通用转换脚本，没有量化能力 |
| 量化图 | 不存在 |
| 低精度判据 | 只有"自相对"的历史做法，不可用 |
| 精度自证手段 | 需要把逐层精度写进引擎，否则无法证明"真的在跑低精度" |

## Existing Limitations

1. 隐式校准路线已废弃 → 只能走显式量化节点。
2. 默认量化配置**非对称**，运行时直接拒绝。
3. 判据缺少出处：低精度不能沿用浮点那一套阈值。

## Extension Points

- **产图脚本的量化开关**：尺度来源、粒度、对称性都在这里决定。
- **逐层精度自证**：把"引擎真的在跑低精度"从推断变成**可读的事实**。
- **产物形态**：预量化常量 vs 量化-反量化对，影响引擎体积。
