# Design

> **性质**：历史设计回填（2026-10-01）。从 `docs/dev/REQ-008-int8-qdq/phase4_int8_plan.md` §1 技术前提 / §2 方案 /
> §3 任务分解抽取，**未新增当时的决定**。

## Overview

低精度量化走**显式量化节点**（Q/DQ），不走已废弃的隐式校准；量化图复用既有外部图路径。

## Architecture

```text
外部参考权重 ──→ 外部图 ──(插对称 Q/DQ)──→ 量化图 ──→ 既有外部图构建入口 ──→ 引擎
                      ↑
                 产图脚本（量化尺度在此计算并写入）
```

## Module Design

| 任务 | 做什么 |
|---|---|
| 工具链调研 | 确认当前运行时版本的量化体系 = 显式 Q/DQ；确认产图可行性 |
| 产图 | 产出**对称** Q/DQ 的外部图（默认权重逐张量对称） |
| 判据 | 定义并落地低精度判据（阈值纪律） |
| 产物形态 | 权重图形态决策：预量化常量 vs 量化-反量化对 |

## Data Structure

- 量化尺度：每个量化张量一份；权重可按张量或按通道。
- 元数据：产物来源、哈希、量化配置——用于回答"这份产物是怎么来的"。

## Runtime Flow

```text
离线：外部队列权重 → 外部图 → 插 Q/DQ → 量化图（+ 元数据）
在线：量化图 → 构建入口 → 引擎（构建期融合 Q/DQ 与卷积）→ 推理
```

## Resource Lifecycle

- **产物身份要钉死**：正式产物与"复现样本"是两回事，不能混用。
- 默认行为与正式产物要**逐字节可复现**。

## Performance Consideration

- 收益来自**显存带宽**（权重 4 字节 → 1 字节），不是张量核心吞吐——目标芯片没有张量核心。
- 若 Q/DQ 未被尊重（弱类型网络下的风险），应先停下汇报，再决定是否做强类型改造。

## Trade-off

| 方案 | 触发条件 | 代价 |
|---|---|---|
| **A 主线：在自己产图时插对称 Q/DQ（采用）** | 默认 | 需要自己保证对称性与尺度来源 |
| B 外部量化库 | A 的导出路径被证伪 | 需额外依赖（**联网，要单独批准**）；产出同样是量化图，后续步骤相同 |
| C 原生构建器里插 Q/DQ | A、B 都不可用 | 需要对每个卷积插节点并自实现校准统计，工作量最大且最容易做出精度不明的东西 |
| C1 强类型网络改造 | 证明"弱类型下 Q/DQ 不被尊重" | 两条构建器的每个算子都要显式设类型；**届时应先停下来汇报** |

**产图路径的实测修正**：最初打算用现成的静态量化流程，实测发现其默认配置**非对称**、
运行时直接拒绝 → 主线不变（仍自己产图），但具体路径改为显式对称量化。

## 工具链调研结果（原 PH4-INT8-TOOLCHAIN）

**结论先写：运行时侧没问题，瓶颈在产图工具链。**

| 实验 | 做法 | 结果 |
|---|---|---|
| S2-a | 现成静态量化流程（默认配置）→ 导出图 | ✅ 导出成功（33 量化 + 83 反量化节点，校验通过） |
| S1-a | 该图走既有构建入口 | ❌ **解析期失败**：不支持非零零点 —— 默认流程产出的是**非对称**量化 |
| S2-b | 自建对称配置 | ❌ **量化没生效**（量化节点数为 0，且**不报错**——静默不量化） |
| S1-b | **手搓的最小对称 Q/DQ 图**走既有构建入口 | ✅ 解析与构建都成功；低精度配置下量化节点与卷积**融合成一层**，并消除了单精度版的重排节点；引擎 **13620 B vs 单精度版 16588 B** |

**三条可执行结论**：

1. **弱类型网络下 Q/DQ 被接受** → 强类型改造**不必要**，主线可以继续；
2. **量化必须对称（零点 = 0）** → 不能用现成默认配置，必须自己产出 int8 对称 Q/DQ；
3. **逐层精度可读已闭环**：默认详细度下引擎检查器只给层名；**设为详细模式后，逐层精度与
   tactic 都能读出来**。实测证据（最小对称 Q/DQ 图）：量化层与卷积融合成 `CaskConvolution`，
   权重类型 `Int8`、数量 108，tactic 名带 `i8i8_i8i32` 与 `tensor8x8x16` ——
   **"引擎在跑低精度"从此有直接证据**，不再依赖层融合 / 体积这类间接推断。

⚠️ 两个后续会踩的细节：① 文本化的执行计划里**没有**低精度标签，必须判格式 / 数据类型字段
（按标签判会误判成"没有低精度"）；② **量化节点是显式类型约束，不受构建精度配置影响**——
同一张量化图在单精度与低精度两种配置下**都**跑低精度卷积，所以"引擎是不是低精度"只能看层信息。

**仍未证的那一小块**：S1-b 用的是手搓最小图；"在完整网络上按真实尺度跑低精度"需在产图打通后复验。
