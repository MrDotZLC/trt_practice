# Test Plan

> **性质**：历史用例回填（2026-10-01）。来源：`docs/dev/REQ-008-int8-qdq/phase4_int8_plan.md` §4 判据与出处 /
> `docs/dev/REQ-007-resnet18/phase4_test_plan.md` 的低精度行。**判据以 `requirement.md` 为准**（含逐条作废标记）。

## Unit Test

- 产图脚本自证：对称性、尺度来源与被量化对象一致。
- 元数据完整（来源 / 哈希 / 量化配置），能回答"这份产物是怎么来的"。

## Integration Test

- 量化图能建出可推理引擎（构建期 Q/DQ 与卷积融合）。
- **"引擎真的在跑低精度"的自证**：把逐层精度写进引擎后再读出来——
  声明的精度必须能被证明，不能靠假定。

## Regression Test

- 默认路径与正式产物**逐字节可复现**（默认行为未被本条目改动）。
- 浮点路径不受影响。

## Failure Test

- 低精度不达标时只允许三选一：继续查 / 证明期望值本身错并给独立依据 /
  标"已知失败 + 原因未知"保持红色。**禁止**调阈值、删断言、降级成打印。

## Expected Result

低精度按**率**达标（主判据 = 有余量样本子集的一致率），并附样本量。

## Actual Result

达成；交付期间发现并修掉"量化尺度取自另一份张量"的根因（该教训升格为通用纪律）。

## Status

已交付（历史条目）。
