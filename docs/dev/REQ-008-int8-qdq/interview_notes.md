# Interview Notes

> **性质**：历史面试口径回填（2026-10-01）。低精度量化是本项目最"硬"的一块，
> 因为它同时要求**数值正确**与**判据可信**。

## Project Introduction

"给视觉模型做低精度量化：不用已废弃的隐式校准，自己产**对称** Q/DQ 图；并且要能**证明**
引擎真的在跑低精度，而不是嘴上说。"

## Architecture Explanation

量化发生在**图**上（离线），运行时只负责构建与执行；量化节点与卷积在构建期融合。
判据按"分层一致率"给（主判据用有余量样本的子集）。

## Key Decisions

| 决策 | 选择 | 理由 |
|---|---|---|
| 量化体系 | **显式 Q/DQ** | 隐式校准在当前版本已废弃 |
| 对称性 | **必须对称（零点 = 0）** | 默认配置产出的非对称图被运行时直接拒 |
| 是否强类型改造 | **不需要** | 最小对称图证明弱类型下 Q/DQ 被接受且融合 |
| 规模 | per-tensor 起步 | 保守、可解释；per-channel 另立项 |

## Technical Challenges

1. **"静默不量化"**：自建对称配置时量化算子数为 **0** 且**不报错**——不查产物就会以为在做量化。
2. **"真的在跑低精度"要能自证**：默认详细度下只给层名；打开详细模式后能读到逐层精度与 tactic，
   从此不靠"层融合/体积"这类间接推断。
3. **两个反直觉细节**：执行计划里没有低精度标签（要判数据类型字段）；量化节点是显式类型约束，
   **不受构建精度配置影响**。

## Trade-offs

- 自己产图 → 换来路线可控，代价是要自己保证对称性与尺度来源正确。
- 逐层精度开关默认关 → 换来引擎体积与构建时间，代价是"要自证时才打开"。

## Interview Questions

### Level 1

Q：为什么不用校准器？　A：当前版本已废弃该路线并推荐显式量化节点。

### Level 2

Q：为什么量化必须对称？　A：非对称图（非零零点）被运行时解析期直接拒绝。

### Level 3

Q：怎么证明引擎在跑低精度？　A：打开详细模式读逐层精度与 tactic；量化层会与卷积融合成一层。

### Level 4

Q：低精度判据为什么不能用浮点那套？　A：精度特性完全不同；且阈值跨精度复用等于把尺子放宽上千倍。

### Level 5

Q：这次踩到最深的一个坑？　A：**量化尺度必须取自被量化那张张量本身**——取错来源会让整网静默崩坏。
