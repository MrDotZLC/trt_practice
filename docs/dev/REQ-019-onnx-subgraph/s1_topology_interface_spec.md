## 0. 已核实的既有能力（决定 S1 的改动面）

| 事实 | 证据 | 对 S1 的意义 |
|---|---|---|
| 现有识别是**计数级** | `tools/inspect_onnx.py` 的 `check()`：比对 `opset` / 输入输出名 / `initializer` 数 / 7 类算子计数 / `absent_ops` | 计数护栏**原样保留**，S1 只在其上加一层 |
| 注意力"块数"由 `Softmax` 计数当代理 | 同文件 `recognize_subgraphs()`：`attention_blocks = ops.get("Softmax", 0)` | 这正是"计数相同、连接不同"识别不出来的根源：12 个 Softmax 可以连成完全不同的图 |
| 三项识别断言写在 `--check` 里 | 同文件 `main()`：`blocks(Softmax) == 12 and matmul == 25 and transpose == 48`、LayerNorm 25、位置编码非 RoPE | 这三条是 **S1 要升级的对象**，升级后旧断言不得删除（`design.md` 的 Risk 表：二者都要过） |
| 已有造小图的夹具工具 | `tools/make_tiny_onnx.py`：`onnx.helper` 拼图，参数化输入 / 输出名 | S1 的**反例图**用同一套工具造，不需要 652MB 资产 |
| 缺 `onnx` 包或缺资产时按既有约定处理 | `inspect_onnx.py` 的 `SKIP_EXIT_CODE = 77` + `require_assets()`；`tools/convert/onnx_to_mini_trt_llm.py` 有同名同义实现 | S1 的新检查沿用同一套"缺环境跳过 / 缺资产判失败"约定，**不新造一套** |

## 1. 拓扑判据的可验证定义

**连接级冲突的定义**（这才是 S1 要拒绝的东西）：

> 两张图的**算子计数完全相同**（逐类相等），但存在至少一条**张量连接**不同，
> 使得"注意力块"的边界不再成立。

对 GPT-2 的注意力块，S1 检查的最小骨架是**边界与主线**，而不是逐算子模式匹配：

| 检查项 | 内容 | 不成立即失败 |
|---|---|---|
| T1 块数 | 沿 `Softmax` 每个实例往回追，能得到**互不共享**的块输入（12 条）；两个 Softmax 共享同一个 `MatMul` 输入即算冲突 | 块数 ≠ 12 或存在共享 |
| T2 主线形状 | 每个块内：`Gemm`/`MatMul` 产生的 QKV → `Split` → `Transpose` → `MatMul` → `Softmax` → `MatMul` → `Transpose`，且 Softmax 的两个输入都来自**同一个块内** | 断链、跨块引用 |
| T3 层间归属 | 每个块的输出经 `Gemm` 回到残差主线，且该块的 `Softmax` **不在**残差主线上 | 块输出被接到别处 |
| T4 位置编码 | 位置编码仍是学习式（`absent_ops` 不含 RoPE 类算子），且其输出**先于**第一个注意力块进入主线 | 位置编码被搬到块内或消失 |

**为什么用"边界 + 主线"而不是全图同构**：全图同构在 `Split` / `Transpose` 这类
等价形态上有大量写法（导出器版本一变就误报），而"块边界 + 谁喂谁"是**语义级**的，
且足以抓住"计数相同、连接不同"。

## 2. 接口

```text
python mini_trt_llm/tools/inspect_onnx.py <onnx> --check              # 计数级（不变）
python mini_trt_llm/tools/inspect_onnx.py <onnx> --check-topology     # 新增：连接级
python mini_trt_llm/tools/inspect_onnx.py <onnx> --check --check-topology   # 两条都要过
```

**报告格式**（失败时逐条打印，便于定位而不是只报一个数）：

```text
拓扑识别失败：
  - T2 主线断链：Softmax(node=Softmax_3) 的第 1 个输入来自 MatMul_17，不在同一块内
  - T1 块数：12 != 11（块边界重叠：MatMul_9 被 2 个 Softmax 共用）
```

退出码沿用现行约定：`0` = 通过；`1` = 图结构不符；`77` = 缺环境（`--skip-if-missing` 且无 `onnx` 包）；
缺资产时按 `MINI_TRT_REQUIRE_ASSETS` 决定 `1`（失败）还是 `77`（跳过）。

## 3. 与计数护栏的关系（不得互相取代）

| 护栏 | 抓什么 | S1 后 |
|---|---|---|
| `--check`（计数 + `absent_ops`） | 图**整体**变了：opset、I/O、算子分布、出现 RoPE 类算子 | **原样保留**，判据不变 |
| `--check-topology`（连接级） | 计数没变但**连接**被改写 | 新增 |

两者**都要过**才算通过。理由是：计数护栏能抓"换了模型 / 换了导出器"这类整体变化，
拓扑护栏抓"同一套算子被重新接线"这类局部变化——覆盖面不同，缺任一条都会留下盲区。

## 4. 反例夹具（S1 的核心交付）

必须造出**计数完全相同、连接不同**的图，否则这条护栏无法被证明有效：

| 夹具 | 造法 | 期望 |
|---|---|---|
| F1 计数不变、连接互换 | 取一张小图，把两个注意力块的 `Softmax` 输入对调（算子与计数一个不变） | `--check` **通过**（计数没变），`--check-topology` **失败** |
| F2 共享输入 | 让两个块共用同一个 `MatMul` 的输出（计数仍不变） | `--check` 通过，`--check-topology` 失败（T1） |
| F3 正常小图 | 造一张**结构正确**的最小注意力块图 | 两条护栏都通过（防"只会报红"的假护栏） |

F1 / F2 用 `make_tiny_onnx.py` 的造图能力扩展（或新增 `make_tiny_onnx.py --rewire` 一类开关）；
**F3 是必须的**：只有负例的护栏无法证明它不会把正确图判错。

**注意**：F1–F3 是**夹具级**验证，不能替代"真实资产图通过 `--check-topology`"这一条
（见 §6）。

## 5. 判据与来源

| 判据 | 来源 |
|---|---|
| 真实图的块数与形态（12 块 / 25 LayerNorm / 学习式位置编码） | 既有 `BASELINE` 首次实测（2026-09-25），升级后**引用它、不重抄数值** |
| 连接级判据 T1–T4 | 本文件 §1 的定义；每条失败必须能打印**具体节点名与张量名**（防止"结论对、证据空"） |
| 反例必须被拒 | F1 / F2 / F3 三条夹具用例（§4） |
| 缺环境 / 缺资产的行为 | 沿用 `SKIP_EXIT_CODE` + `require_assets()`（本次不新造约定） |

## 6. 测试方式

| 用例 | 判据 | 环境 |
|---|---|---|
| `inspect_onnx --check-topology`（真实资产图） | 通过；块数与块边界与计数基线一致 | 沙箱（需 `onnx` + 资产；缺资产按 `MINI_TRT_REQUIRE_ASSETS` 处理） |
| F1 连接互换 | `--check` 通过、`--check-topology` 失败且报出对调的两个块 | 沙箱（夹具自造，无资产依赖） |
| F2 共享输入 | 同上（报 T1） | 沙箱 |

| 全量回归 | 既有 `--check` 用例不变红 | 沙箱 |

**S1 不需要真机**：全部判据都是 host 侧图结构检查（这是它在"PF-7 待真机"期间仍可完成的原因）。
