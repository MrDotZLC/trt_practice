## Current Architecture

外部图路径的现状是一条**直线**：

```text
ONNX 文件
   ↓ 读取 + 逻辑检查（文件是否存在、子图名是否在白名单）
   ↓ 解析器解析进网络定义
   ↓ I/O 契约检查（输入名 / 输出名必须与原生路径同名同义）
   ↓ 只挂"整段前向"一组 profile
   ↓ 构建 → 序列化 → 指纹落盘
```

**没有任何图变换环节**：解析出来的网络原样构建。子图名参数只做"名字合法性校验"，
真正的识别落在 Python 侧脚本里，而且只做**计数级**识别。

## Module Structure

| 模块 | 现状职责 | 是否支持替换 |
|---|---|---|
| 外部图构建入口 | 解析、契约检查、profile、构建、缓存 | **否** |
| 识别脚本（Python） | 算子计数 + 与固定基线比对 + 缺失算子护栏 | 只计数，不拓扑 |
| 插件注册表 | 持有自研算子的创建器（归一化 / 旋转位置编码 / 分页注意力） | 具备被解析器调用的能力，但**当前无使用者** |
| 插件本体 | 三个插件实现（含序列化 / 反序列化） | 已具备 |
| 原生路径 | 手写算子组合建图 | 替换的**目标实现**来源 |
| 引擎缓存 | 指纹含外部图文件身份、构建参数、版本 | 已具备（换图必重建） |
| 对拍用例 | 两条路在同一 prompt 上的数值对比 | 已具备（但只覆盖整段前向） |

## Data Flow

```text
外部图 ──(解析)──→ 网络定义 ──(原样)──→ 引擎
                                        ↑
                             自研算子实现 ✗ 未接入
```

对照原生路径：

```text
配置 + 权重 ──(手写算子组合)──→ 网络定义 ──→ 引擎
                                              ↑
                                  自研算子实现 ✓ 已接入
```

## Runtime Flow

- 外部图引擎构建后与原生引擎用法相同**到"绑定张量"为止**；但两者的输入契约不同
  （元素类型不同、位置编码输入有无不同），所以**不能互换调用方**。
- 外部图的引擎只挂整段前向的 profile，**不带 K/V 缓存输入**，也就是说它目前只覆盖 prefill。

## Existing Limitation

1. **无图变换环节**：解析出来即构建，没有任何插入 / 替换 / 重连的位置。
2. **识别只到计数**：无法区分"算子数量相同但连接不同"的图（这是缺口 G5 的定义）。
3. **自研算子在外部图路径上零使用者**：插件注册表已就绪，但没有任何图会产生这些算子。
4. **收益未证明**：两次测量方向相反，差异小于构建间噪声。
5. **契约不一致**：外部图的输入元素类型与原生路径不同、且缺位置编码输入
   → 接不进统一运行时（`docs/future_iterations.md` §10.1）。
6. **外部图只有 prefill**：没有 decode 图与 K/V 输入，因此"替换注意力"当前只能替换整段前向那一段；
   若要让外部图成为一等公民，要先补 decode 侧。
7. **目标模型的可替换面很窄**：GPT-2 用的是 LayerNorm 与学习式位置编码，
   **不含**旋转位置编码与 RMSNorm；而 LayerNorm 用 TensorRT 原生层已经足够。
   因此这条路上真正可替换的只有**注意力子图**，可替换面比"三个插件都能用"的直觉小得多。
8. **解析器未挂插件注册表**：外部图构建入口用的是 `createParser(*network, logger_)`。
   即便图上出现 `mini_trt_llm` 域的算子，当前实现也不会去插件注册表找创建器——
   "让自定义算子在外部图上被执行"这条路当前**不可达**（不是配置问题，是构造参数缺一项）。
9. **PF-7 缺少实现用例**：`OnnxVsNative.PerfPerBuildMedian` 这个用例名**全仓只在测试计划里出现**，
   代码里没有；`tests/test_gpt2_onnx.cpp` 现有的测量是"各跑 5 次取平均、单次构建、不出极差"，
   达不到 PF-7 自己声明的"≥3 次构建 × ≥20 次推理、报中位数与极差"。
   （测试计划原文曾记"无新代码"，该表述已于 2026-10-06 更正。）

## Extension Point

- **Python 侧**：图重写工具链已经存在（造夹具脚本、识别脚本），加一个"重写并导出"的脚本
  是同一套工具的自然延伸。
- **自定义算子导出**：本项目的算子需要以自定义域算子出现在图里，解析器才会去插件注册表找创建器——
  这是 `docs/future_iterations.md` §6.2 的内容，尚未做。
- **C++ 侧**：网络定义没有通用的"子图替换"原语，但按层名定位、重建算子、重连 I/O 在原理上可行
  （成本与脆弱性见设计阶段的对比）。
- **识别**：现有脚本已经能拿到算子与连接信息，升级到拓扑级是在同一份数据上做更多判断。

## Terminology

> `requirement.md` 里的模糊名词逐个给**可验证定义**（P1 规则：定义必须能回答
> "怎样算做到了、怎样算没做到"）。未在此定义的模糊名词不得进入 `design.md`。

| 名词 | 可验证定义 |
|---|---|
| **原生路径（方案 A）** | 由本项目配置 + 权重、用手写算子组合建图的路径。判据：输入为 `input_ids` + `position_ids`，两者 INT32 |
| **外部图路径（方案 B）** | 把一张 ONNX 图整段交给解析器的路径。判据：当前输入只有 `input_ids` 且为 INT64，且只挂 prefill profile |
| **计数级识别** | 只比较"某类算子出现了几个"与固定基线。做到 = 计数与基线一致；做不到 = 计数同但连接不同时仍然报通过 |
| **拓扑级识别** | 除计数外，还比较子图的入口张量、出口张量与内部算子之间的连接关系。做到 = 能对"计数相同、连接不同"的图报失败并指出差异；没做到 = 该图报通过 |
| **子图替换** | 把图中一个子图整体换成一个自定义域算子节点，**边界张量名保持不变**。做到 = 替换后引擎可构建、可序列化 / 反序列化、可推理，且边界名未变；没做到 = 边界名变了、或引擎不可用 |
| **自定义算子 / 自定义域算子** | 以本项目 domain（`mini_trt_llm`）注册、由本项目的插件创建器实例化的算子。做到 = 解析期由插件注册表找到创建器（非 TensorRT 内置层替代）；没做到 = 解析失败或落回内置层 |
| **契约统一（同一套调用方式）** | 同一份输入张量集合与 dtype 能绑定两条路的引擎并完成推理。做到 = 用同一份 `input_ids` + `position_ids`（INT32）可分别喂给两条路；没做到 = 某一方需要额外准备转换或缺失的输入 |
| **替换生效** | 替换后的引擎里**确实**执行了自研算子。判据 = 引擎逐层 ONELINE 原文里出现插件层（先落盘原文再定断言）；没做到 = 只能证明"图重写脚本跑过了"，引擎里没有任何插件层痕迹 |
| **PF-7 / 可复现对照** | 同一 session 内、≥3 次构建 × ≥20 次推理，报每次构建的中位数与极差。做到 = 报出构建次数、推理次数、中位数、极差；没做到 = 单次测量或跨 session 拼接数字 |
| **可判 / 未定** | 极差 < 中位数差 = 可判（差异超得出噪声）；极差 ≥ 中位数差 = 未定（任何更小的效果都不可观测）。未定**不等于**"没有差异" |
| **有出处的判据** | 每个数值阈值旁写明它来自哪次实测 / 哪个标准 / 哪份文档；且不得跨精度复用。没做到 = 只有阈值、说不出出处 |
