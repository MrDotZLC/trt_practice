# Analysis

> **性质**：历史分析回填（2026-10-01）。来源：本目录 `phase4_development_plan.md` §1 历史工程盘点 / §3 架构。

## Current Architecture

框架此前只覆盖语言模型。视觉模型是另一条独立需求，而历史工程**没有留下可用的外部基线**
（它当年的"精度验证"是自相对，输入还是合成数据）——因此"数值对齐"缺少标尺。

## Data Flow

```text
外部参考权重 → 外部图（已折批量归一化）→ 路径 A：外部图构建入口 → 引擎
             └→ 转换工具 → 原生权重 → 路径 B：原生构建器 → 引擎
                        ↓
                  三方对拍：A / B / 外部参考基线
```

## Relevant Modules

| 模块 | 开工时状态 |
|---|---|
| 外部参考基线 | **不存在**（历史工程是自相对判据） |
| 外部图路径 | 有骨架，但 I/O 契约写死语言模型 |
| 原生构建器 | 不存在 |
| CV 运行时 | 不存在 |
| 前处理契约 | 从未跑过（历史推理路径喂合成数据） |

## Existing Limitations

1. 没有外部基线 → 所有"对齐"结论无依据。
2. 前处理契约未定义 → 数值误差会被误判成"引擎错"。
3. 历史工程**继承不到**四样东西：外部基线、前处理、原生权重 + 配置、性能结论。

## Extension Points

- **I/O 契约按 architecture 分支**：让同一份构建入口同时服务语言与视觉两条路径。
- **权重转换工具**：把"外部图 → 原生权重 + 配置"变成可重复流程。
- **CV 运行时**：把前处理与推理收在一个可测的边界里。
