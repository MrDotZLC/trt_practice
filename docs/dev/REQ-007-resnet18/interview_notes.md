# Interview Notes

> **性质**：历史面试口径回填（2026-10-01）。仅覆盖"视觉路径"这一条目；低精度部分见 `REQ-008`。

## Project Introduction

"把视觉模型接进同一个推理框架：先造一条**外部基线**（历史工程没有），再走原生与外部图两条路，
三方对拍——注意原生那条**一个自定义插件都不需要**。"

## Architecture Explanation

两条接入路径：先复用外部图构建入口（改动最小），再做原生建图并用前者对拍。
两者共用同一份 I/O 契约常量，因此"两条路对齐"是干净的判据。

## Key Decisions

| 决策 | 选择 | 理由 |
|---|---|---|
| 接入顺序 | **先外部图、后原生** | 外部图改动小、能最快拿到可运行引擎；原生风险集中在转换工具，后置后可用前者对拍 |
| 基线来源 | **外部参考实现（FP32）** | 与产图脚本同源，且**不需要联网** |
| 前处理契约 | **运行时自己做归一化** | 与基线脚本逐参数一致，否则误差会伪装成"引擎错" |
| 最优批量 | 默认值 1 → **8** | 否则批量 ≥2 走非最优内核，性能结论失真 |

## Technical Challenges

1. **历史工程继承不到四样东西**：外部基线、前处理、原生权重 + 配置、性能数字 → 都得新建。
2. **判据不能自相对**：只跟自己的单精度比，只能证明"两种精度自洽"，证明不了"对"。
3. **量化尺子必须量对对象**：这一阶段踩的坑后来写成通用纪律——
   量化尺度必须取自**被量化那张张量本身**。

## Trade-offs

- 先外部图后原生 → 换来快速可跑，代价是原生路径的验证被推后。
- 保留合成输入作为"与旧实现逐值可比"的一套，另加真实图 → 换来两类证据互补。

## Interview Questions

### Level 1

Q：视觉路径做了什么？　A：造基线、通两条路径、跑通运行时、三方对拍。

### Level 2

Q：为什么原生建图不需要插件？　A：批量归一化已在导出时折进卷积，剩下的算子运行时都有原生层。

### Level 3

Q：为什么不用历史工程的判据？　A：那是自相对判据，且输入是合成数据——证明不了"对"。

### Level 4

Q：前处理为什么放在运行时？　A：契约要能被测试；与基线脚本逐参数一致才不会把误差误判成引擎错。

### Level 5

Q：低精度判据为什么改？　A：原口径是分布外输入间的一致性，对低精度**不成立**（必然饱和）；
改成"有余量样本子集的一致率"。
