# Review Report

> **性质**：历史评审回填（2026-10-01）。来源：本目录 `phase4_development_plan.md` §0.5 决策 / §7 风险。

## Summary

评审聚焦四个决策（接入路径 / 是否纳入低精度 / 基线来源 / 前处理契约）与一条**关键结论**：
原生建图**不需要任何自定义插件**。

## Checklist Result

| Item | Level | Result | Action |
|---|---|---|---|
| 基线必须先于一切 | P0 | 没有可复现基线则所有对齐无依据 | 排为第一任务 |
| 前处理契约一致 | P0 | 不一致会让误差伪装成"引擎错" | 与基线脚本逐参数一致 |
| 原生建图是否需要插件 | P0 | **不需要**：批量归一化已折进卷积，算子都有原生层 | 工作量落在权重映射与形状校验 |
| 低精度判据 | P1 | 判据在交付中被**整体替换**（见下） | 改用分层一致率 |
| 批量档位 | P1 | 默认最优批量应为 8 而非 1 | 否则批量 ≥2 走非最优内核，性能结论失真 |

## P0 Blockers

无遗留（三处 P0 开工前定案）。

## P1 Risks

| 风险 | 影响 | 缓解 |
|---|---|---|
| 基线不可复现 | 后续结论全无依据 | 要求脚本自证（两次运行逐位一致） |
| 前处理契约不一致 | 数值差被误判成引擎错 | 契约先定死，两侧共用同一套参数 |
| 低精度不达标 | 与语言模型的 FP16 事故同型 | 保持红色并记录，**不调阈值** |
| 旧模块被误删 | 失去对拍对象 | 删除前必须先迁资产（后续条目） |

## P2 Quality

两条路径共用 I/O 契约常量；配置里的描述性字段不参与建图决策。

## Decision

**PASS**（低精度判据按实测改写为分层口径，见 `test_plan.md`）。
