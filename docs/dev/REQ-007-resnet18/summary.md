# Project Summary

> **性质**：历史交付总结回填（2026-10-01）。来源：本目录 `phase4_development_plan.md` §6 / §8 / §10。

## Problem

框架只覆盖语言模型；视觉模型没有可用基线（历史工程是自相对判据 + 合成输入），
且"对齐"缺少标尺、前处理从未跑过。

## Solution

先造外部基线，再走两条路径（外部图 / 原生）并三方对拍；把前处理契约定死；最后纳入低精度量化。

## Architecture

```text
外部参考权重 → 外部图 ─┬→ 路径 A：外部图构建入口 → 引擎
                       └→ 转换工具 → 原生权重 → 路径 B：原生构建器 → 引擎（零 Plugin）
                                  ↓
                          三方对拍（A / B / 外部基线）
```

## Implementation

基线 → 外部图路径 → 运行时封装 → 原生构建器 + 转换工具 → 三方对拍 → 低精度 → 文档收口。

## Performance

**无可用对照**（历史无数字、输入不同）。唯一性能相关决策：最优批量 1 → 8。
详见 `benchmark_before.md` / `benchmark.md`。

## Limitation

- 动态分辨率**不做**（空间维固定），留作开放项。
- 低精度判据在交付中被**整体替换**：原"分布外输入一致性"口径作废，改用分层一致率
  （主判据 = 有余量样本子集一致率，整体一致率只作下界）。
- 交付期间踩到的"量化尺子量错对象"事件，后来成为一条**通用纪律**。
