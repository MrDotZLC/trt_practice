# Design

> **性质**：历史设计回填（2026-10-01）。从 `docs/dev/REQ-007-resnet18/phase4_development_plan.md` §0.5 决策 /
> §3 架构与接口设计抽取，**未新增当时的决定**。

## Overview

让框架独立承载视觉模型的构建与推理：先复用外部图路径拿到可运行结果，再做原生建图并对拍。

## Architecture

```text
                     ┌── 路径 A（先做）：外部图 ──→ 外部图构建入口 ──→ 引擎
外部参考权重 ────────┤                                                    │
                     └── 路径 B（后做）：外部图 ──→ [转换工具] ──→ 原生权重 ──→ 原生构建器 ──→ 引擎
                                                          + 配置
                     ↓
              三方对拍：A / B / 外部参考基线
```

## Module Design

| 模块 | 职责 | 依赖 |
|---|---|---|
| 外部图路径 | 复用既有入口，仅把 I/O 契约按 architecture 分支 | 既有构建入口 |
| 转换工具 | 从外部图导出原生权重 + 配置（含权重映射） | 外部图 |
| 原生构建器 | 用原生层拼网络（**不需要任何自定义插件**） | 转换工具 |
| CV 运行时 | 前处理 + 推理 + 基准 | 引擎 |
| 基线脚本 | 产出外部参考基线（含元数据与哈希） | 外部参考权重 |

## Data Structure

- 配置：模型类型 + architecture + 描述性超参 + **权重映射表**（原生路径必需）。
- 基线元数据：脚本 / 版本 / 权重哈希 / 输入来源与形状 / 逐样本 argmax。
- 前处理契约：输入为原始像素质（NCHW），归一化由运行时完成；**必须与基线脚本逐参数一致**。

## Runtime Flow

```text
基线脚本（离线）→ 参考输出 + 元数据
运行时：原始像素质 → 归一化（纯函数）→ 引擎 → 分类输出
对拍：原生 vs 外部图 vs 参考基线
```

## Resource Lifecycle

- 基线产物入库（小体积 + 哈希）；权重与图不进版本控制，按文档重建。
- 引擎缓存指纹覆盖架构 / 精度 / 构建参数。

## Performance Consideration

- 批量的 **opt 取值影响性能结论**：历史工程用 8，沿用 1 会让 batch ≥ 2 走非最优 kernel
  → 默认值由 1 改为 8。
- 动态分辨率**不做**（空间维固定），留作开放项。

## Trade-off

| 编号 | 决策 | 选择与理由 |
|---|---|---|
| D1 | 接入路径 | **先外部图、后原生**：外部图改动小、能最快拿到可运行引擎，原生风险集中在转换工具，后置后可用外部图结果对拍 |
| D2 | 是否纳入低精度量化 | **见 `docs/dev/REQ-008-int8-qdq/design.md`**（2026-10-01 按需求拆出） |
| D3 | 参考基线怎么来 | **外部参考实现（FP32）**：与产图脚本同源、权重已在本地缓存，**生成基线不需要联网** |
| D4 | 前处理契约 | **运行时自己做归一化**：与基线脚本逐参数一致，否则误差会伪装成"引擎错" |

**关键结论**：原生建图**不需要任何自定义插件**——该图已把批量归一化折进卷积，
算子在运行时都有原生层；工作量在权重映射与形状校验。

## 历史工程盘点（原 PH4-LEGACY-FINDINGS / PH4-LEGACY-INHERIT）

### 事实

- 模型来源：外部参考实现（ImageNet 预训练）；图 opset 17，输入为图像张量、**批维动态**。
- **权重 42 个、全为单精度**（20 个卷积 = 40 个权重/偏置 + 1 个全连接 = 2 个）。
- 算子：卷积 20 / 激活 17 / 加 8 / 最大池化 1 / 全局平均池化 1 / 展平 1 / 全连接 1。
- **批量归一化已折叠进卷积**（图里既无该算子、也无乘除）→ 原生建图不需要任何插件。
- 单 profile：批 1/8/16，空间维固定；三条精度路径都实现过；低精度用 500 张真实图校准。
- **历史判据是自相对的**：低精度与它自己跑的单精度比；推理输入是**合成 ramp**，
  基准输入是**常量张量**——两者都不能作为外部真值。

### 继承 / 弃用

| 继承 | 理由 |
|---|---|
| profile 取值、输入名、类别数、ImageNet 前处理参数 | 与图和权重同源的既有事实，改了就没有对齐基准 |
| 低精度的**校准集**（500 张真实图） | 现成的真实分布数据，重建成本高（需联网） |
| 基准的批量扫描点 | 便于与历史数据横比 |

| 弃用 | 理由 |
|---|---|
| 自相对判据 | 它证明不了"对"，只证明"两种精度自洽"→ 必须引入**外部基线** |
| 合成 ramp 作为**唯一**输入 | 覆盖不到真实分布与前处理；保留它作为"与旧实现逐值可比"的那一套，另加真实图 |
| 隐式量化 | 运行时版本已废弃 |

### 历史工程**继承不到**的东西（本阶段必须新建）

1. **外部基线**：从没对过外部参考的数值 → 必须先造。
2. **前处理**：历史上从未跑过 → 必须先定契约。
3. **原生权重 + 配置**：不存在 → 需转换工具。
4. **性能结论**：历史只留了方法、**没留任何数字** → 若要报性能，按既有可复现口径重测，
   **不引用不存在的旧数据**。
