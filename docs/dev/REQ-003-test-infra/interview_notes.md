# Interview Notes

> **性质**：历史面试口径回填（2026-10-01）。

## Project Introduction

"第三阶段：让框架的端到端链路**可自动验证**——不是测试里手工挂几个插件，而是真的走
'配置 + 权重 → 引擎 → 推理'，同时把动态形状的优化配置补齐。"

## Architecture Explanation

测试侧的关键设计是**测试专用构建器与真实构建器同构**：权重从文件读出、按名字映射挂成常量，
复用同一条权重加载链路——绕开它就等于没测。

## Key Decisions

| 决策 | 选择 | 理由 |
|---|---|---|
| 是否复用被测实现的公式 | **不复用**，另写独立参考 | 参考必须独立，否则测不出实现错 |
| 测试构建器是否绕开权重加载 | **不绕开** | 绕开就失去"全流程测试"的意义 |
| 静态形状还是动态 | **静态先行** | 避免把"profile 未实现"混进"链路是否打通" |

## Technical Challenges

**缺陷不可后置**：权重加载的指针生命周期问题在 2 个权重时是 bug、在 150 个权重时是灾难，
且症状是**静默建错**而非崩溃——所以它排在所有任务最前。

## Trade-offs

- 引擎构建慢 → 用"同一 fixture 合并断言 + 引擎缓存复用"换测试时间。
- 只做单步串联 → 换来"链路是否打通"与"自回归循环是否正确"两个问题的分离。

## Interview Questions

### Level 1

Q：为什么要有端到端测试？　A：算子单测证明"算子对"，不证明"算子接在一起对"。

### Level 2

Q：测试怎么拿到权重？　A：用权重写入 helper 构造真实的权重文件，走同一条加载链路。

### Level 3

Q：为什么要独立参考实现？　A：复用被测实现的公式推导，错误会被同样复制一份。

### Level 4

Q：动态形状怎么测？　A：同一引擎在不同形状上推理、超范围必须显式失败并给可诊断错误。

### Level 5

Q：最难的取舍是什么？　A：测试成本 vs 覆盖——引擎构建是分钟级，必须合并断言并复用缓存。
