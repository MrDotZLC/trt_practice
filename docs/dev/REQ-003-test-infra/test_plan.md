# Test Plan

> **性质**：历史用例回填（2026-10-01）。来源：`docs/dev/REQ-003-test-infra/phase1_5_test_plan.md` §2 用例清单。
> **判据以 `requirement.md` 为准**（含 E4 的"3 条沙箱 + 2 条真机"更正）。

## Unit Test

错误路径用例在 **host 侧**即可运行、进 CI（不依赖 GPU）——这是本阶段为"CI 防线"专门建立的一层。

## Integration Test

**E1 单算子最小模型闭环（4 条，真机）**：归一化 / 旋转位置编码 / 分页注意力 / logits 直采。
判据 = 与独立参考的 FP32 绝对误差 < `1e-4`；采样器那条比对 CPU argmax。

**E2 多算子串联（2 条，真机）**：

| 用例 | 判据 |
|---|---|
| 完整链路与独立 CPU 参考一致（权重全部来自权重文件） | 与独立 CPU 参考对比；**FP16 走独立档，阈值不跨精度复用** |
| 权重映射指向不存在的 key 时必须建网失败 | 返回 false 且不产出引擎 |

**E3 动态 shape（3 条，真机）**：预填充接受变化的序列长度 / 解码接受变化的批量 /
超范围形状被拒并给出可诊断错误。

## Regression Test

**一并收口的覆盖缺口（3 条 FP16，真机）**：旋转位置编码的 FP16 + GQA + 多批、
分页注意力的 FP16、采样器的 FP16。

## Failure Test

**E4 错误路径（5 条）**：无配置 / 未注册模型类型 / 缺权重文件 / 权重映射指向不存在的 key /
构建期失败向上传播且不落引擎。前三者在沙箱，后两者在真机。

## Expected Result

沙箱全绿且 GPU 用例显式跳过不产生噪声；真机通过；缺 profile 时报可诊断错误。

## Actual Result

全部达成；其中 E4 的口径**被更正过一次**（原写"五条沙箱通过"，实为三条沙箱 + 两条真机）。

## Status

已交付（历史条目）。
