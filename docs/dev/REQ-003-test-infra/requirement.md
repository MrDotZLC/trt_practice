## Problem

上一阶段的算子只在测试里被"手工挂载"验证过，没有走真实的调用链；同时动态形状的
optimization profile 只声明未实现，是下一阶段的硬前置；另外盘点发现两个会污染下一阶段的底层缺陷。

## Goal

1. 让"配置 + 权重 → 引擎 → 推理"这条链路有**可自动运行**的端到端测试。
2. 把算子按**真实调用方式**（经模型构建器 + 权重加载器 + 构建入口）串起来验证，
   而不是在测试里手工挂载插件。
3. 补齐下一阶段的硬前置：动态形状的 optimization profile。
4. 修掉会污染下一阶段的底层缺陷。

## Scope

### Included

- 权重加载路径的生命周期与指针稳定性修复。
- 权重写入辅助工具（供测试构造权重文件）。
- 错误路径用例。
- 单算子最小模型闭环；多算子串联的 mini decoder 单步链路。
- optimization profile 的实现与双 profile（预填充 / 解码）测试。
- 文档归位与验收判据改写为可执行形式。

### Excluded

- 完整的多步解码循环（属下一阶段）。
- 分页注意力的预填充阶段。
- 采样器的性能优化。

## Acceptance Criteria

来源：`docs/phase1_5_development_plan.md` §5（7 条）。

1. 底层缺陷修复各有针对性回归用例，且**都不需要 GPU 即可运行**。
2. 沙箱 `ctest` 全绿，GPU 用例以显式跳过方式呈现、不产生噪声。
3. 错误路径用例：三条沙箱实际执行并通过，另两条真机通过。
4. 单算子闭环四条用例在真机通过，FP32 绝对误差 < `1e-4`。
5. mini decoder 的 logits 与独立参考在阈值内；FP16 变体按既定决策判定。
6. 双 profile 用例三条在真机通过，且覆盖最优形状。
7. 未配置 profile 而输入含动态维时，报**可诊断**错误。
8. 文档动作完成（含把前一阶段的验收判据改写为可执行形式）。

## Constraints

- 缺陷修复**不可后置**：症状是静默错误而非崩溃，后置会污染下一阶段。
- 测试用构建器必须与真实构建器同构——绕开权重加载链路会让"全流程测试"失去意义。
- 静态形状先行，避免把"profile 未实现"混进"链路是否打通"的判断。
- Runner 当时仍是桩，不要为了"更像端到端"而顺手实现它。
