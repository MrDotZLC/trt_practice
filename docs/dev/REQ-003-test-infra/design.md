# Design

> **性质**：历史设计回填（2026-10-01）。从 `docs/dev/REQ-003-test-infra/phase1_5_development_plan.md` §2 任务总览 /
> §3 任务详细说明 / §6 注意事项抽取，**未新增当时的决定**。

## Overview

把"配置 + 权重 → 引擎 → 推理"变成可自动运行的端到端测试，并补齐下一阶段的硬前置。

## Architecture

```text
测试侧                          ← 与外层同构，但用测试专用构建器
  ├─ 权重写入 helper            ← 构造权重文件（测试基建）
  ├─ 测试专用 IModelBuilder     ← 与真实构建器同构，不绕开权重加载链路
  └─ 端到端用例（单算子 / 多算子 / 动态形状 / 错误路径）
产品侧
  └─ optimization profile 实现   ← 下一阶段的硬前置
```

## Module Design

| 任务 | 做什么 | 依赖 |
|---|---|---|
| P1.5-0 | 修权重加载的**指针生命周期**与映射注释（缺陷，必须先做） | 无 |
| P1.5-1 | 权重写入 helper（测试基建） | 无 |
| P1.5-2 | 错误路径用例（host 侧，进 CI） | 与 P1.5-1 并行 |
| P1.5-3 | 单算子最小模型闭环（4 条） | P1.5-0 / P1.5-1 |
| P1.5-4 | 多算子串联（mini decoder 单步） | P1.5-3 |
| P1.5-5 | optimization profile 实现 | P1.5-4 |
| P1.5-6 | 预填充 / 解码双 profile 测试 | P1.5-5 |
| P1.5-7 | 文档归位（含把上一阶段判据改写为可执行形式） | 全部 |

**并行关系**：P1.5-0 / P1.5-1 / P1.5-2 互不依赖，可并行；自 P1.5-3 起严格串行。

## Data Structure

- 权重映射表：运行期名字 → 权重源 key。
- profile：动态输入的 min / opt / max 三元组；预填充与解码各挂一组。

## Runtime Flow

```text
测试构造（config.json + 权重文件） → 构建入口 → 建网 → buildSerializedNetwork
   → 落盘 → 运行时加载 → 设形状 → 绑定 → 推理 → 与独立参考对比
```

## Resource Lifecycle

- **权重指针稳定性是设计要点**：转换结果按张量名缓存，保证运行时不变量拿到的裸指针在整次建图期间有效。
- 引擎文件按 `模型类型 + 形状` 缓存复用，避免每条用例重复构建（分钟级成本）。

## Performance Consideration

- 不追求性能；**关注测试成本**：同一 fixture 的多条断言合并为一条用例，避免重复构建引擎。
- 静态形状先行，避免把"profile 未实现"混进"链路是否打通"的判断。

## Trade-off

| 决策 | 选择 | 为什么 |
|---|---|---|
| 测试专用构建器是否绕开权重加载 | **不绕开** | 绕开就失去"全流程测试"的意义 |
| 缺陷修复能否后置 | **不能** | 症状是静默错误而非崩溃，后置会污染下一阶段 |
| 是否顺手实现 Runner | **不做** | 属下一阶段范围，混进来会让失败归因不清 |
