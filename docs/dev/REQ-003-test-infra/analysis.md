# Analysis

> **性质**：历史分析回填（2026-10-01）。来源：本目录 `phase1_5_development_plan.md` §0 / §3 / §6。

## Current Architecture

上一阶段交付了算子，但验证方式是"测试里手工挂载插件"——**没有走真实调用链**；同时优化配置
（profile）只声明未实现，是下一阶段的硬前置；盘点还发现两个会污染下一阶段的底层缺陷。

## Data Flow

端到端测试要走的链路：

```text
测试构造（config.json + 权重文件）→ 构建入口 → 权重加载（按名字映射）→ 构建器 →
网络 → 序列化 → 引擎 → 设形状 → 绑定 → 推理 → 与独立参考对比
```

## Relevant Modules

| 模块 | 开工时状态 |
|---|---|
| 权重加载 | 存在，但**指针生命周期有缺陷**（转换缓冲互相覆盖） |
| 权重文件写入 | 测试侧无 helper，无法构造权重夹具 |
| 优化配置（profile） | 只有声明，无实现 |
| 端到端用例 | 只有算子级单测 |

## Existing Limitations

1. 算子只被"手工挂载"验证过，真实调用链没有被测。
2. 权重加载的缺陷在 2 个权重时是 bug，在 150 个权重时是灾难——下一阶段一定会撞上。
3. 动态形状能力不可用（profile 未实现），而它是双引擎方案的前置。

## Extension Points

- **权重写入 helper**：后续所有需要"真实权重夹具"的端到端用例都靠它。
- **测试专用构建器**：与真实构建器同构，是"全流程测试"的骨架。
- **优化配置实现**：一次写好，后续预填充 / 解码双 profile 直接继承。
