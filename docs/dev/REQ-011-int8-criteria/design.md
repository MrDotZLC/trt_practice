# Design

> **性质**：历史设计回填（2026-10-01）。从 `docs/future_iterations_development_plan.md` §2.2 抽取，
> **未新增当时的决定**。

## Overview

把"低精度怎么算合格"从散落的口径变成**可执行的规格 + 脚本**，且全程不下载数据。

## Architecture

```text
验收集规格（什么数据才配被引用）
        ↓
分层统计脚本（读 logits + 元数据 → 输出分层报告）
        ↓
护栏自检（证明脚本真的会拦人）→ 进 ctest
        ↓
判据表与测试计划指向新规格（先改文档）
```

## Module Design

| 步骤 | 做什么 | 关键约束 |
|---|---|---|
| A2-1 写规格 | 验收集"必须有什么字段才能被引用"：来源 / 版本 / 哈希 / 标签 / **与标定集的重叠排除规则** | 规格里可以写"将来到哪里取数据"，但**本轮不执行任何下载** |
| A2-2 写分层统计 | 输出分层报告：每层给**率 + 样本量 n** | 口径与运行时现役实现**必须一致**（同一定义、同一分桶边界来源） |
| A2-3 加护栏自检 | 对**7 类**输入必须拒绝，每种都要有一份"故意改坏"的输入把它打出来 | 护栏没有用例证明"它会拦人"就等于没有护栏 |
| A2-4 不下载 | 全程离线 | 这是本条与其他低精度条目最大的区别 |

## Data Structure

```text
分层报告 = 每层 { 一致率, 样本量 n }（率不带 n 等于没有判别力）
绝对误差只在"有余量的子集"上报 p50 / p95 / p99
```

## Runtime Flow

```text
logits + 元数据 → 分层统计 → 报告（率 + n）→ 与运行时侧口径比对
```

## Resource Lifecycle

- 脚本与规格入库；验收集不入库（它体积大且需联网获取）。
- 缺 Python / 缺资产时按约定返回跳过码（返回 77 → 跳过），不判失败。

## Performance Consideration

不涉及性能。

## Trade-off

| 决策 | 选择 | 为什么 |
|---|---|---|
| 与运行时实现的关系 | **只做口径对齐，不重构运行时侧** | 两侧各写一份实现必须**互校**，但不能在本条里顺手改产品代码 |
| 数据来源 | **本轮不下载** | 联网须单独批准；离线那一半独立可完成 |
| 判据落点 | **先改文档再改脚本** | 判据表与测试计划的出处必须先指向新规格 |
