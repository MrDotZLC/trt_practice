# Project Summary

> **性质**：历史交付总结回填（2026-10-01）。来源：本目录 `future_iterations_development_plan.md` §2.2。

## Problem

低精度的合格线散落在计划正文与用例代码里：没有数据规格、没有独立脚本、没有自检，
判据无法复核，"为什么这个率可接受"答不上来。

## Solution

把"低精度怎么算合格"写成**可执行的判据规格 + 脚本**，全程**不下载数据**（离线可完成的那一半）。

## Architecture

```text
规格（验收集必须有的字段：来源 / 版本 / 哈希 / 标签 / 与标定集的重叠排除）
        ↓
分层统计脚本 → 报告（每层：率 + 样本量 n）
        ↓
护栏自检（7 类非法输入各备反例）→ 进 ctest
        ↓
判据表与测试计划的出处改指向新规格（先改文档）
```

## Implementation

A2-1 写规格 → A2-2 写分层统计（与运行时侧口径对齐）→ A2-3 加护栏自检 → A2-4 不下载；
并把判据表与测试计划的出处改指到新规格。

## Performance

**不适用**。

## Limitation

- **只覆盖原需求的离线一半**：下载带真值标签的验收集仍未做（需联网，须单独批准）。
- 绝对误差**仍不作判据**：这批图上单精度自身摇摆，绝对差被少数样本放大。
