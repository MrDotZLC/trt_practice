## Problem

低精度的"合格线"此前只散落在计划正文与用例代码里：没有验收集规格（什么样的数据集才配被引用），
也没有独立于运行时实现的分层统计脚本。结果是判据无法被复核——"这个率是怎么算的"只有一处实现。

## Goal

把"低精度怎么算合格"写成**可执行的判据规格 + 脚本**，且**不下载任何数据**（离线可完成的那一半）。

## Scope

### Included

- **验收集规格**：一个数据集"必须有什么字段才能被引用"（来源 / 版本 / 哈希 / 标签 /
  与标定集的重叠排除规则）。
- **分层统计脚本**：读 logits 与元数据 → 输出分层报告（每层：率 + 样本量）。
- **口径一致性**：脚本侧与运行时侧**必须一致**（同一定义、同一分桶来源）。
- **护栏自检**：脚本要有一个能证明"它真的会拦人"的自检项。
- 把新规格接进判据表（**先改文档**）。

### Excluded

- **下载带真值标签的验收集**（需联网，属原需求的另一半，未完成）。
- 改运行时侧的统计实现（只做口径对齐，不重构）。

## Acceptance Criteria

来源：`docs/future_iterations_development_plan.md` §2.2 的步骤与产物。

1. 验收集规格落盘，明确"缺字段即不可引用"。
2. 分层统计脚本产出报告，**每层的率都带样本量 n**（率不带 n 等于没有判别力）。
3. 脚本与运行时侧口径一致（同定义、同来源）。
4. 脚本的护栏自检进 `ctest`；缺 Python / 缺资产时按约定返回跳过码而不是失败。
5. 判据表与测试计划的相关出处指向新规格（**先改文档再改代码**）。

## Constraints

- 全程**不下载数据**：这是它与其他低精度条目最大的区别。
- 率必须带样本量；绝对误差只允许在有余量的子集上报告分位数。
- 阈值不许跨精度复用。
