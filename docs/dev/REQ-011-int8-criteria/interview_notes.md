# Interview Notes

> **性质**：历史面试口径回填（2026-10-01）。

## Project Introduction

"给低精度量化定一把**可复核的尺子**：什么样的验收集才配被引用、率怎么算、样本量怎么报——
全程离线，而且脚本自己要先被自检证明'它会拦人'。"

## Architecture Explanation

规格 → 脚本 → 自检 → 判据表改指。核心是**两把尺子互校**：脚本侧与运行时侧必须口径一致。

## Key Decisions

| 决策 | 选择 | 理由 |
|---|---|---|
| 数据来源 | **本轮不下载** | 联网需单独批准；离线那一半可独立完成 |
| 与运行时实现的关系 | **只对齐口径，不重构** | 两侧各一份实现必须互校，但不能在本条顺手改产品代码 |
| 率的呈现 | **必带样本量 n** | 率不带 n 等于没有判别力 |
| 绝对误差 | 只在**有余量子集**上报分位数 | 全样本 max 会被少数样本放大 |

## Technical Challenges

**"护栏没有用例证明它会拦人，就等于没有护栏"**——7 类非法输入各备一份故意改坏的样本，
脚本必须拒绝；拒绝不了就说明护栏是假的。

## Trade-offs

- 只做离线一半 → 换来本轮零外部依赖，代价是绝对误差判据继续悬空。
- 两侧实现都要留 → 换来互校，代价是要维护同一口径的两份代码。

## Interview Questions

### Level 1

Q：这份脚本干什么？　A：读结果与元数据，输出分层的"率 + 样本量"报告。

### Level 2

Q：为什么要规格？　A：不是任何数据集都配被引用——来源、版本、哈希、标签、与标定集的重叠排除都要有。

### Level 3

Q：怎么保证脚本本身可信？　A：带自检，对 7 类非法输入必须拒绝；自检进 ctest。

### Level 4

Q：为什么率要带样本量？　A：样本少时率的判别力很弱，不带 n 的率是误导。

### Level 5

Q：为什么绝对误差当时不作判据？　A：这批图上单精度自身摇摆，绝对差被少数样本放大——
要定它必须先有带真值标签的验收集。

## Follow-up Questions

- 两边口径怎么保证一致？（同定义、同分桶来源，并要求实测互校）
- 有什么是这件事没解决的？（绝对误差界仍为空，且验收集还缺真值标签）
