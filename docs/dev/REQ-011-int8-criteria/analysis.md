# Analysis

> **性质**：历史分析回填（2026-10-01）。来源：本目录 `future_iterations_development_plan.md` §2.2。

## Current Architecture

低精度的"合格线"此前只散落在计划正文与用例代码里：**没有验收集规格**（什么样的数据集才配被引用），
也**没有独立于运行时实现的分层统计脚本**。结果是判据无法被复核——"这个率是怎么算的"只有一处实现。

## Data Flow

```text
验收集（须满足规格）→ 分层统计脚本 → 报告（每层：率 + 样本量 n）
                       ↕ 口径必须与运行时侧现役实现一致
                    护栏自检（证明脚本真的会拦人）→ 进 ctest
```

## Relevant Modules

| 模块 | 开工时状态 |
|---|---|
| 验收集规格 | 不存在 |
| 分层统计脚本 | 不存在（只有 C++ 侧的现役统计） |
| 脚本自检 | 不存在 |
| 判据表 | 出处未指向规格 |

## Existing Limitations

1. 判据无可复核的规格 → "为什么这个率可接受"答不上来。
2. 只有一处实现 → 口径错了也发现不了（需要两侧互校）。
3. 率不带样本量 → 判别力无从判断。

## Extension Points

- **规格文件**：定义"什么样的数据才能被引用"，是后续所有低精度判据的前提。
- **分层统计脚本**：与运行时侧**互校**的第二把尺子。
- **护栏自检**：让"脚本被改坏"这件事自动暴露。
