# Project Summary

> **性质**：历史交付总结回填（2026-10-01）。来源：本目录 `phase2_development_plan.md` §4 / §6 / §8。

## Problem

算子与测试基建已就绪，但没有真实模型跑通；双引擎、分页缓存与自回归循环三件事都还缺。

## Solution

用原生层建出语言模型的两张图（预填充 / 解码），落地分页 K/V 缓存，并跑通
"预填充 → 解码 → 采样"的自回归循环（循环内零主机-设备同步拷贝）。

## Architecture

```text
权重 + 配置 → 构建器 → 两张图
   ├─ 预填充：整段前向 + 每层导出 K/V
   └─ 解码  ：单 token + 分页注意力插件
                 ↑ 分页 K/V 缓存（每层一对独立张量）
   Runner：预填充 → 解码循环（位置编码由设备端长度填）→ 追加 K/V（整步一次）→ 采样
```

## Implementation

前置改造（构建选项 / 权重映射 / 切面 profile）→ 多权重加载验证 → 能力确认（归一化 / 激活 /
取词嵌入用原生层即可）→ 建图与缓存 → 三组测试（预填充精度、解码一致性、端到端生成）。

## Performance

**不适用**（无性能目标）。已知工程成本：引擎构建分钟级、显存吃紧。

## Limitation

- **FP16 端到端数值不稳定**：产出 NaN，且出现 NaN 的层随构建变化；当时判据从"达标"降级为
  "量化记录"，并登记为**已知限制**。推荐精度为 **FP32**。
- 文本分词、批量调度、低精度量化都**不做**（各有独立条目）。
- Runner 只支持单序列。
