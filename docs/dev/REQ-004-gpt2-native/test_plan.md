# Test Plan

> **性质**：历史用例回填（2026-10-01）。来源：`docs/dev/REQ-004-gpt2-native/phase2_test_plan.md` §3/§4/§7。
> **判据以 `requirement.md` 为准**；阈值出处见下表。

## Unit Test

主机侧：权重映射与元数据校验、归一化轴的参考实现（meta test）、缓存布局契约
（覆盖跨块边界与批量 > 1）。

## Integration Test

| 层 | 内容 | 环境 |
|---|---|---|
| L0 | 权重与配置解析、形状校验（含真实转换产物的约 150 个权重） | 沙箱 |
| L1 | 建网契约（预填充 / 解码两张图的 I/O 与输出数） | 真机 |
| L2 | 预填充对拍参考基线；**解码一致性**（单步 / 两步 / 空缓存） | 真机 |
| L3 | 真实模型贪心 8 token 与外部参考逐 token 一致；温度拒绝对照 | 真机 |

## Regression Test

逐位置 argmax / 逐 token 一致作为**语义判据**（"token 是产品判据，数值是定位判据"）。

## Failure Test

- 未注册的模型类型、缺失权重、温度非 1 —— 均须显式失败。
- 构建期失败必须向上传播且不落引擎。

## Expected Result

四层全绿；FP32 端到端 8/8 命中。

## Actual Result

L0~L3 通过；**FP16 端到端出现 NaN**（判据从"达标"降级为"量化记录"），
该问题后来登记为已知限制并派生独立条目。

## Status

已交付（历史条目）。
