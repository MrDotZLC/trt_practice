## Problem

框架有了算子与测试基建，但还没有任何真实语言模型跑通：没有原生建图、没有分页缓存的解码路径、
没有自回归循环。同时项目硬约束要求解码循环内不得出现主机与设备之间的同步拷贝。

## Goal

1. 由 `config.json + model.safetensors` **原生**建出可分发（经注册表）的网络。
2. 预填充路径（整段 prompt 一次前向）输出 logits，与参考基线数值对齐。
3. 解码路径接入分页注意力插件，K/V 缓存**全程驻留显存**，逐 token 前向结果与预填充自洽。
4. Runner 跑通"预填充 → 解码 → 采样"自回归循环，**循环内零主机-设备同步拷贝**。
5. 精度基准从"仅与外部实现对拍"升级为"对拍 + 解码一致性"两条独立判据。

## Scope

### Included

- 语言模型的原生建图（含权重常量、归一化、注意力子图、激活、残差）。
- 双引擎切面：预填充（整段前向 + 导出每层 K/V）与解码（单 token + 分页缓存）。
- 分页 K/V 缓存的写入与追加契约。
- 自回归循环与采样器接入。

### Excluded

- 文本分词（当时只收发 token id）。
- 分页注意力的预填充阶段（预填充用原生算子拼）。
- 批量与连续批调度（只做到"能跑通"）。
- 低精度量化与显存池。
- 温度、重复惩罚等采样参数。
- 视觉路径。

## Acceptance Criteria

来源：`docs/phase2_development_plan.md` §6（10 条）。

1. 沙箱 `ctest` 全绿（主机用例实际执行，GPU 用例显式跳过）。
2. 能由真实配置与权重建出预填充 / 解码两个引擎。
3. 预填充 FP32 logits 与参考基线在阈值内一致，且**贪心 token 完全一致**。
4. FP16 的偏移被**量化记录**（不接受"只要不崩就算过"）。
5. 解码路径与预填充逐位置自洽。
6. K/V 布局契约有独立单测，覆盖跨块边界与批量 > 1。
7. 贪心 8 token 与外部参考完全一致。
8. 循环内零主机-设备同步拷贝（代码审查 + 可选系统级分析佐证）。
9. 文档收口。
10. 每个里程碑都走一遍**真机验证**，不留到下一阶段。

## Constraints

- 解码循环内禁止主机-设备同步拷贝（项目硬约束）。
- 目标机显存有限，源权重 + 两个引擎 + 缓存会吃紧。
- 判据阈值必须写明出处；FP16 与 FP32 的尺子不可混用。

## 历史演进（抽取时保留）

  该问题后来登记为已知限制，并派生出一条独立的需求条目。
- 第 1 条的用例条数是当时快照，不要当现在的基线。
