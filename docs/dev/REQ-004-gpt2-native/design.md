# Design

> **性质**：历史设计回填（2026-10-01）。从 `docs/dev/REQ-004-gpt2-native/phase2_development_plan.md` §0 开工前事实核对 /
> §1 目标与非目标 / §3 任务总览抽取，**未新增当时的决定**。

## Overview

让语言模型真正跑通：原生建图 → 预填充前向 → 分页缓存 → 解码路径 → 自回归循环。

## Architecture

```text
配置 + 权重 ──(GPT2 构建器)──→ 两张图
                                ├─ 预填充：整段前向，除 logits 外每层导出 K/V
                                └─ 解码  ：单 token，读分页缓存，注意力走自研插件
                                        ↓
                                   分页 K/V 缓存（块池 + 块表 + 长度）
                                        ↓
                                   Runner：预填充 → 解码循环 → 采样
```

## Module Design

| 阶段 | 任务 | 依赖 |
|---|---|---|
| 前置改造 | 构建选项增加"切面 + 权重类型"；转换工具产出原生配置与**权重映射表**；profile 按切面过滤 | — |
| 风险验证 | 多权重加载 spike（真实权重约 150 张量） | 转换工具 |
| 能力确认 | 归一化 / 激活 / 取词嵌入的原生层能力确认 + host 参考实现 | — |
| 开发 | 语言模型构建器（预填充 + 解码两张图）；KV 缓存落地；Runner 循环 + 采样器接入 | 前置改造 |
| 测试 | 预填充精度对拍；**解码一致性**；端到端生成 | 开发 |

**里程碑**：M1 能建出来且数值对 → M2 KV 缓存与解码自洽 → M3 端到端能生成。

## Data Structure

- 权重映射表：运行期名字 → 权重源 key（把权重改名与建图代码解耦）。
- 分页缓存：块池 + 每序列块表 + 语境长度；**每层一对独立的缓存张量**。
- 构建选项：切面（单引擎 / 仅预填充 / 仅解码）+ 权重类型 + 诊断开关。

## Runtime Flow

```text
预填充：[B,S] 前向 → logits 取末行 → 每层 K/V 写入分页缓存（长度推到 S）
   ↓
解码循环（零 H2D/D2H）：位置编码由设备端长度填充 → 引擎 → 追加当前 token 的 K/V
   （整步只推一次长度）→ 采样 → 下一个 token
   ↓
循环结束后一次性取回结果
```

## Resource Lifecycle

- 权重转换结果按张量名缓存，保证裸指针在整次建图期间稳定（上一阶段修过的同类缺陷在 150 个张量规模上会放大）。
- 引擎按 `切面 + 精度` 缓存；重编译后由构建指纹判定是否复用。
- 缓存显存常驻，不在解码循环内分配。

## Performance Consideration

- 目标是"跑通且自洽"，不是性能；性能画像留到后续迭代。
- 已知成本：建引擎为分钟级（大常量 + 多层），因此测试间共享 fixture。
- 显存吃紧：源权重 + 两个引擎 + 缓存，需按阶段先后（先单精度定位、再低精度交付）。

## Trade-off

| 决策 | 选择 | 为什么 |
|---|---|---|
| 引擎切分 | **预填充 / 解码双引擎** | 两者注意力结构不同；单引擎会互相拖累，且预填充用原生子图即可 |
| 预填充注意力 | **原生算子拼的子图** | 当时不改分页注意力插件（其预填充支持被冻结） |
| 文本分词 | **不做** | 分词与数值是两个问题，混在一起无法归因 |
| 采样参数 | 只支持温度 = 1 且**显式拒绝**其他值 | 静默忽略会让"调参无效"看起来像模型特性 |
