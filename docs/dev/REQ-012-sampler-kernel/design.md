# Design

> **性质**：历史设计回填（2026-10-01）。从 `docs/future_iterations_development_plan.md` §10.3 接口与设计 /
> §10.11 决策抽取，**未新增当时的决定**。

## Overview

在**语义完全不变**的前提下降低每步采样开销。

## Architecture

```text
每行一个 block：
  一趟 strided 扫描（行 max / sum）→ 寄存器内候选（阈值迭代收紧）→ 块内归并 top-M
     → 只对 M 个候选排序 → 采样数学（与现状逐条一致）
```

## Module Design

| 决策 | 内容 | 为什么 |
|---|---|---|
| **D1 接口形态不变** | 只允许改工作区大小查询的**返回值**与注释；签名、参数结构、错误约定一律保持 | 调用方只查询大小，不感知内部实现 |
| **D2 算法** | 每行一个 block；寄存器候选 + 阈值迭代；块内归并；只排序候选；**采样数学与随机数消费逐条对齐现状** | 语义不变是本条的硬约束 |
| **D3 隐式契约显式化** | 既有实现依赖"相同 logits 时保持原下标顺序"（并列取小下标）——新实现必须在块内排序时**显式**保证，并用用例锁住 | 隐式依赖不清除，换实现就会出现"偶发不同 token" |
| **D4 数值路径不变** | 指数函数、减行 max 稳定化、CDF 比较符号、Top-P 在保留前缀内重新归一化——逐条与现状对齐 | 这就是"语义不变"的具体含义 |

## Data Structure

- 工作区：调用方提供；大小由启动函数查询（查询值可变，结构不变）。
- 候选集：每行 M 个（M 自适应）。

## Runtime Flow

```text
logits 行 → 扫描求分母 → 候选筛选 → 块内归并 → 候选排序
   → 逆变换采样（消费同一个随机流）→ token
```

## Resource Lifecycle

- 不在启动函数内分配显存；工作区由调用方持有。
- 不引入主机侧同步。

## Performance Consideration

- **必须同二进制 A/B**：把改动前后两版编进同一个二进制，同一轮正反交替测，
  报净成本（斜率）的中位数与四分位。
- 平台的判别下限约几百微秒；**低于下限只能写"无显著差异"**。

## Trade-off

| 决策 | 结果 |
|---|---|
| Top-K 侧：整行排序 → 部分选择 + 只排候选 | 正确性通过，但**实测更慢**（根因：占用率与共享内存冲突）→ **撤出生产路径**，库内保留待重做 |
| Top-P 侧：**保留排序**、只把行内数学块内并行化 | 采纳（见 §10.11 的方案收窄） |
| 收尾段进一步并行化 | 实施后同二进制 A/B 判"无显著差异"→ 代码保留为永久对照入口，**不设判据** |
| 第一趟访存的进一步优化 | **不做**：净开销已接近"裸读一遍行"，优化空间见底 |
