# Analysis

> **性质**：历史分析回填（2026-10-01）。来源：本目录 `future_iterations_development_plan.md` §10.2 / §10.11。

## Current Architecture

Top-K / Top-P 采样每步都要对**整行词表**做一次降序排序（词表可达 12.8 万），是每步的固定开销；
同时采样器的低精度分支与大词表边界缺少覆盖。

## Data Flow

```text
logits 行 → 扫描求分母（行 max / sum）→ 候选筛选（寄存器内 top-M）→ 块内归并
        → 只对候选排序 → 采样数学（保持与现状逐条一致）→ token
```

## Relevant Modules

| 模块 | 开工时状态 |
|---|---|
| 采样器 kernel（三套：贪心 / Top-K / Top-P） | 已实现，但 Top-K / Top-P 走整行排序 |
| 工作区查询接口 | 存在（调用方只查询大小） |
| 低精度分支覆盖 | 缺 Top-K / Top-P |
| 大词表覆盖 | 缺 |

## Existing Limitations

1. 整行排序 → 每步开销与词表规模成正比。
2. 缺低精度与大词表的边界覆盖。
3. 没有**同二进制 A/B** 的对照入口，改动效果无法在同轮内判。

## Extension Points

- **工作区大小查询**：只改返回值即可扩容，接口形态不动。
- **并行化切入点**：每行一个 block，行内数学可块内并行。
- **A/B 入口**：把两版都编进同一个二进制，是同轮配对测量的前提。
