## Problem

Top-K / Top-P 采样每步都要对整行词表做一次降序排序，在长词表下是明显的每步开销；
同时采样器的低精度分支与大词表边界缺少覆盖。

## Goal

在**语义不变**的前提下降低每步采样开销，并补齐覆盖：
Top-K 侧把"整行降序排序"换成"每行先选出部分候选、只对候选排序"；
Top-P 侧**保留排序**、只把行内数学块内并行化。

## Scope

### Included

- 先测基线，据此决定"是否换实现"以及性能判据的阈值（**阈值必须由实测给出**）。
- 新 kernel：块内归并出部分候选 → 只对候选排序 → 采样走新路径。
- 补齐低精度（Top-K / Top-P）与大词表的用例。
- 报告性能（中位数与极差）并回填文档。

### Excluded

- **不改**采样器公共接口形态（设备侧、每批参数、调用方提供 workspace）。
- 不引入主机侧同步、不在启动函数内分配显存。
- 不做连续批调度、不做温度/重复惩罚等新采样语义。
- 不改贪心实现（它已是单次比较，无排序）。

## Acceptance Criteria

来源：`docs/future_iterations_development_plan.md` §10.5。

1. **语义回归（主判据）**：采样器既有用例**不改判据、全部通过**；解码与低精度路径的相关用例通过。
2. **低精度覆盖**：新增 Top-K / Top-P 的低精度用例，判据沿用既有分布口径（与解析概率的比较）。
3. **大词表覆盖**：在合成大词表与真实词表形状下，Top-K 结果必落在解析 top-K 集合内、
   Top-P 结果必落在解析 nucleus 内。**这两条不设阈值**（集合成员关系判定，无阈值即无出处问题）。
4. **性能**：对冻结基线的门槛达标；报告用中位数与极差，且必须**同二进制 A/B**。

## Constraints

- 语义不变是硬约束：新路径必须与旧路径逐 token 一致。
- 性能结论必须先量基线、再由实测定阈值；不接受拍脑袋的达标线。
- 同平台存在测量判别下限，低于它不能说"更快"。

## 历史演进（抽取时保留，勿按旧值验收）

- **Top-K 快速路径被撤回**：正确性通过，但实测比旧路径慢数倍（根因与重做方向有记录），
  **已从生产路径撤下**，库内保留待重做。因此"本条达标"只对 Top-P 成立。
- **收尾段优化（后续子项）**：实施后经同二进制 A/B 判定"无显著差异"→ 代码保留、
  **不设判据**，作为永久对照入口。
- 第 4 条的性能阈值由实测给出，跨 session 的数字**不可直接比**（该项目为此吃过一次亏）。
