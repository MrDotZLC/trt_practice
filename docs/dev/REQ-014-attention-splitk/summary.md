# Project Summary

> **性质**：历史交付总结回填（2026-10-01）。来源：本目录 `future_iterations_development_plan.md` §12.4。

## Problem

长上下文下注意力占解码每步约 80%（性能画像量出）；机制是每层可并行的块数远少于硬件并行度，
每块要串行走完整个上下文。

## Solution

把解码注意力的**上下文维**切开并行（两阶段归约），**在不放松任何数值判据的前提下**
降低长上下文每步的边际成本。

## Architecture

```text
stage-1（头 × 批 × 分片）：每片算局部 m / l / acc（float 累积）→ workspace
stage-2（头 × 批）：统一 max 后加权归约 → 输出
```

## Implementation

分片策略（纯函数、可离线单测）→ 两条 kernel（FP32 / FP16）→ 工作区契约（按动态形状上界）→
边界用例 → 同二进制 A/B → 真机端到端复验。

## Performance

| 口径 | 结果 |
|---|---|
| kernel 级斜率（ctx 32→1024） | 0.902569 → **0.100609 ms/1000 位置**，**−88.853%** |
| 端到端斜率（prompt 4→960） | 10.795 → **1.2738 ms/1000 位置**，**−88.20%**（两次复现） |
| 短上下文（ctx≈32） | 0.916×（多一次归并发射），**观测项、不设判据** |

## Limitation

- **宿主侧判不出"该不该分片"**：长度在设备上且禁止循环内同步 → 网格恒为上限、每块自查有效片数；
  短上下文因此多发一次归并。
- 逐 kernel 分解在本机不可得（拿不到 GPU 时间线）→ 结论以**斜率与比值**给出。
