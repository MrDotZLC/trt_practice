# Design

> **性质**：历史设计回填（2026-10-01）。从 `docs/future_iterations_development_plan.md` §12.3 接口与设计抽取，
> **未新增当时的决定**。

## Overview

把解码注意力的**上下文维**切开并行，在不放松任何数值判据的前提下降低长上下文的每步边际成本。

## Architecture

```text
stage-1（grid = (heads, batch, splits)）：每块算一段连续逻辑位置的局部 m / l / acc（一律按 float 累积）
        ↓ 写 workspace
stage-2（grid = (heads, batch)）：M = max m_i；l = Σ l_i·exp(m_i−M)；acc = Σ acc_i·exp(m_i−M)
        ↓
     输出 acc / l
```

## Module Design

| 决策 | 内容 | 为什么 |
|---|---|---|
| **D1 切上下文维，不切 head 维** | 只对上下文维分片 | "再细分 head 维"block 数翻倍、每块仍要串行走完整段上下文，延迟不减 |
| **D2 两阶段结构** | 分片 → 归约；**不用跨块原子合并** | 原子累加无法保序 → 结果不可复现，与"可复现"的判据冲突 |
| **D3 工作区** | 必须走工作区机制，尺寸按动态形状的**上界**给 | 按当前形状算会偏小并越界 |
| **D4 分片策略** | 做成主机 / 设备都能调用的**纯函数**，主机侧可裁决 | 切法只有一份实现，避免两处各自演进后静默错位 |
| **D5 旧单趟 kernel 永久保留** | 作为同二进制 A/B 的对照入口与兜底 | 删掉它，A/B 只能靠版本回退 |

## Data Structure

```text
workspace 每片一段：{ m_i, l_i, acc_i[d] }
分片切法：由纯函数按 (总长, 片数, 上限) 决定，返回每片的起点与长度
```

## Runtime Flow

```text
进入 stage-1：每个 block 用自己那份上下文长度算 effective_splits
                超出有效片数的 block 立即返回、不读不写
   ↓
stage-2：只读本行有效范围内的 partial → 输出
```

## Resource Lifecycle

- 工作区按上界申请，由运行时在插件外提供；kernel 内不分配。

## Performance Consideration

- 短上下文多发一次归并（每层一次）是**已知代价**，实测约 1~2%，作为观测项。

## Trade-off

| 决策 | 选择 | 为什么 |
|---|---|---|
| 短上下文是否退化成单趟 | **代码上不可行**：宿主机拿不到当前上下文长度（长度在设备上，且禁止循环内 D2H） → 改为**网格恒为上限 + 每块自查有效片数** | 上一条路要么违反"循环内零同步"，要么改动引擎 profile 语义并牵连另一条路径 |
| 是否用"最后一次发射 + 原子票据归约" | **不用** | 引入跨块内存序依赖，属"看运气"的缺陷类别；本项目历史真 bug 全是数值正确性问题 |
