# Test Plan

> **性质**：历史用例回填（2026-10-01）。来源：`docs/dev/REQ-009-retire-legacy/phase5_development_plan.md` §4.1 / §5.1 /
> §7 / §9。**判据以 `requirement.md` 为准**。

## Unit Test

- **闸门自证（两条 ctest 项）**：从空目录跑一条依赖资产的用例——
  不设闸门时**跳过**、设置闸门时**判失败**。后者用"期望失败"反过来断言"它真的红了"，
  于是**闸门哪天被删掉，这条 test 立刻变红**。

## Integration Test

- **期望跳过集合比对器**：吃一次完整跑出的日志，与基线清单逐条比对；
  集合一变就红。比对器本身带 6 项合成日志断言作为自检（它不进 ctest，否则会递归）。

## Regression Test

- 资产迁移后沙箱**跳过集合逐条不变**（与迁移前对照）。
- 目录删除后真机跳过集合 = 阶段 0 钉住的基线；**删除的唯一可接受后果是"零变化"**。

## Failure Test

- 缺资产 + 闸门开启 → 判失败（而非静默跳过）。
- 缺资产 + 闸门关闭 → 跳过并打印显式探测原因。

## Expected Result

功能不变、覆盖面不减少、覆盖损失可见、资产可重建。

## Actual Result

全部达成；真机全量验收通过，跳过集合与迁移前逐条相同。

## Status

已完成（历史条目，阶段 0~4）。

## 依据：改名实验（原 phase5 §3）

**做法**：把两个目录原地改名（不删、不复制），跑沙箱全量，再改名还原——用来测"覆盖损失对 CI 可见吗"。

| 项 | 改名前 | 改名后 |
|---|---|---|
| ctest 总结 | 265 条，100% passed，0 failed | 265 条，**100% passed，0 failed** |
| 依赖资产的用例 / 探针（3 条） | Passed | **Skipped** |
| gtest 计数 | PASSED 144 / SKIPPED 112 | PASSED 143 / SKIPPED 113 |

**三条结论**：

1. **ctest 的通过信号对这次删除完全不可见**（仍是 265 / 0 failed / 100%）——因为 Skipped 记作 Passed；
2. **只看"有无设备"的闸门拦不住**：它只把"无设备"的跳过变成失败，资产缺失走裸跳过；
3. **静态分析会漏**：有一条自检对资产的依赖写在构建脚本的 `add_test` 参数里，grep 测试源码抓不到。

→ 所以**资产闸门 + 期望跳过集合**是必需的，不能靠人力核对。
