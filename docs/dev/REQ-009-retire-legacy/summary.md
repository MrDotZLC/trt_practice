# Project Summary

> **性质**：历史交付总结回填（2026-10-01）。来源：本目录 `phase5_development_plan.md` §4~§8。

## Problem

两个历史示例工程已不参与构建，但它们的**数据资产**仍是现行测试的判据来源；删掉资产会让相关用例
**静默跳过**，而跳过在 CI 里表现为通过——覆盖损失不可见。

## Solution

按"**先让覆盖损失可见 → 再迁资产 → 最后删目录**"的顺序下线：
加资产闸门 、钉住期望跳过集合、给闸门加正反用例、把资产迁到 `assets/legacy/`、
解除借夹具耦合、删除目录与软链接、真机全量验收。

## Architecture

```text
阶段 0：资产闸门（缺资产→判失败）＋ 期望跳过集合基线 ＋ 闸门自证用例
阶段 1：资产迁移（相对软链接过渡，行为零变化）
阶段 2：解除"借别的模型产物当负例夹具"的耦合
阶段 3：删除 22 个跟踪文件 + 4 条软链接 + 根构建里的旧模块注释；20 处路径改到新位置
阶段 4：真机全量验收 + 文档回填
```

## Implementation

```text
assets/legacy/
├── resnet18_onnx/   图 + 500 张校准数据（保持原文件名）
├── gpt2_onnx/       图 + 唯一的精度基线
├── scripts/         三个重建脚本（按自身路径定位输出目录）
└── README.md        来源 / 获取方式 / 哈希 / 重建命令 / 为什么留着
```

## Performance

**不适用**；唯一被度量的是"跳过集合逐条不变"（见 `benchmark.md`）。

## Limitation

- **校准数据不可离线重建**（需联网下载），因此它的存续是硬约束。
- 删除后首次运行需重建引擎（分钟级，属预期）。
