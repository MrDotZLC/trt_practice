# Analysis

> **性质**：历史分析回填（2026-10-01）。来源：本目录 `phase5_development_plan.md` §2 资产盘点 / §3 改名实验。

## Current Architecture

仓库里还留着两个早期的示例工程目录：它们**已不参与构建**，但其中的**数据资产仍是现行测试的
判据来源**。直接删会连带丢掉资产；不删则路径上始终留着两套过时结构。

## Data Flow

```text
用例 → 旧目录路径 → 命中资产 → 执行
若删掉资产：用例 → 路径不命中 → **静默跳过** → ctest 记为 Passed（覆盖损失不可见）
```

## Relevant Modules

| 模块 | 开工时状态 |
|---|---|
| 资产闸门 | 不存在（缺资产＝静默跳过） |
| 资产的引用面 | 12+ 个用例、多个工具脚本、3 处来源记录 |
| 跳过集合 | 无基线、无比对器 |
| 重建脚本 | 散在旧目录里 |

## Existing Limitations

1. **覆盖损失对 CI 不可见**：跳过被记作通过（有实测证据，见 `test_plan.md`）。
2. "只看有无设备"的闸门拦不住资产缺失。
3. 静态分析会漏：有条自检对资产的依赖写在构建脚本的测试参数里。

## Extension Points

- **资产闸门**：把"缺资产"从跳过改成失败，是后续任何删除动作的前提。
- **期望跳过集合比对器**：让"用例换人但条数不变"这类损失可见。
- **相对软链接过渡**：把"迁移"与"改代码"两个风险源拆开。
