# Benchmark Report

> **性质**：本条目用自己建立的协议回答三个问题。数字是**观测值**（中位数与区间），
> "sampler 占比"这类**不设阈值**——设了就会退化成被禁止的判据。

## Environment

GPU: NVIDIA GeForce GTX 1660 Ti Mobile（`sm_75`，无 Tensor Core）
TensorRT: 10.15.1　CUDA: 12.6.85

## Workload

decode 一步（batch 1）；上下文 4 / 256 / 960；FP32；报告含构建态与温度时钟。

## Measurement

同 session、逐轮交替（ABBA）、报中位数 + p25/p75、并给出三层时间之和与总时间的偏差。

## Comparison

| 问题 | 观测值 | 判据 |
|---|---|---|
| **采样器在整步解码里占多少** | 贪心 **1.25%** / Top-K **17.7%** / Top-P **20.1%** | **观测值，不设阈值** |
| **注意力占多少（长上下文）** | prompt 4 → 960：每步 3.055 → 14.705 ms；**长上下文下 attention ≈ 每步 80%** | 触发长上下文优化立项（`REQ-014`） |
| **显存分配贵不贵** | 全程 `cudaMalloc` **63 次 / 3.335 ms**；`cudaFree` 69 次 / 249.7 ms（拆除期成本） | **触发未获支持** → 显存池不排期 |

## Analysis

- **短上下文**下采样器占比可观（Top-P 约 20%），与 `SamplerPerf` 同 session 互校一致。
- **长上下文**分母变大，同样的 sampler 只占约 3%；真正的瓶颈转移到注意力 → 直接促成 `REQ-014`。
- **显存分配**：分配本身的开销不足以支撑"替换显存池"这类改动 → 记为**触发未获支持**。
- **能力边界**：逐 kernel 分解在本机不可得（拿不到 GPU 时间线），改用"同 session 比值 + 上下文扫描"。

## Decision

**Keep**（采集入口与分桶脚本保留，不进默认构建）。
