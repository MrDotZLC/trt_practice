# Design

> **性质**：历史设计回填（2026-10-01）。从 `docs/future_iterations_development_plan.md` §11.3 测量协议 /
> §11.4 分解口径抽取，**未新增当时的决定**。

## Overview

建立"同一 session 内可复现"的性能测量方法 + 一键采集入口，并用它把解码时间分解到可归因的粒度。

## Architecture

```text
一键采集 target（系统级 / kernel 级）→ 报告落文件，控制台只回摘要 → 分桶脚本（含自检）→ 结论
```

## Module Design

### A. 机器状态固定（能固定的部分）

- 一组对照在**同一 session 内**跑完；记录温度 / 时钟 / 功耗的前后读数；
- 平台通常**不能锁时钟** → 不假装能锁，改用"同轮交替 + 报极差"抵消漂移；
- 关掉其它占用设备的进程，并记进报告。

### B. 两类问题、两种测法（不得混用）

| 问题类型 | 测法 | 报什么 |
|---|---|---|
| **同二进制内的 A/B**（改动有没有用） | 两个变体编进同一二进制，同轮正反交替；每变体测"发射 1 次"与"发射 4 次" | `(T4−T1)/3` = **净成本（斜率）** 的中位数 + 四分位 |
| **跨构建对照**（两条路谁快） | 同 session 内各自 **≥3 次独立构建**，每次 **≥20 次推理** | 每次构建的中位数 + 全部中位数的**极差**；极差 > 中位数之差 → 判"**未定**" |

### C. 判别下限（写死，避免事后改口）

- 本平台此类测量的判别下限约 **±400~600 µs**；
- 观测效应低于下限 → 结论只能写"**无显著差异**"，不许写成"更快 / 更慢 X%"；
- 若"隔离计时"与"时间线"两口径方向相反 → **以隔离计时为准**，并在报告里标注两口径。

### D. 报告格式（缺一项就不算完成）

引擎 / 形状 / 精度、构建态（命中还是重建）、n 与 warmup、中位数 + 四分位、温度时钟前后值、命令原文。

## Data Structure

```text
一次测量记录 = { 形状, 精度, 构建态, n, warmup, 中位数, p25, p75, 温度时钟, 命令 }
```

## Runtime Flow

```text
采集 target → 报告文件 → 分桶脚本 → 三层时间之和 vs 总时间的偏差 → 结论（含偏差）
```

## Resource Lifecycle

- 采集 target **不进默认构建**；用独立引擎路径，避免改动生产契约。
- 报告默认不入库。

## Performance Consideration

本条就是测量方法本身；能力边界：本机拿不到逐 kernel 时间线 → 逐 kernel 分解记为**能力边界**，
改用"同 session 比值 + 上下文扫描"。

## Trade-off

| 决策 | 选择 | 为什么 |
|---|---|---|
| 能否锁定时钟 | **不假设能锁** | 平台通常不支持；假装锁定会让结论失去依据 |
| 采样器占比是否设阈值 | **不设**，只给观测值与区间 | 设阈值会退化成被禁止的判据（它回答的是"占多少"，不是"达标没有"） |
