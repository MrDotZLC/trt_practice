## Problem

1. **语言模型侧没有任何量化**。当前端到端只能跑 FP32（推荐）与 FP16（数值不可用）。
   权重以 FP32 存放，模型体积与显存占用都按 4 字节/参数计。
2. **decode 是访存受限**：每生成一个 token 需要把全部权重从显存读一遍。降低权重的字节数
   是这一档最直接的收益来源。注意本机（GTX 1660 Ti / TU116）**没有 Tensor Core**，
   收益来自**带宽**，不是来自张量核心吞吐——这一点必须说准，否则性能预期会立错。
3. **没有"引擎真的在跑低精度"的自证手段用于语言模型**。视觉模型侧已经有一套
   （逐层精度写进引擎 + 读出每层的实际精度），语言模型侧没有对应的护栏，
   无法排除"声明 INT8、实际静默回落"的情况。
4. **K/V 缓存的元素宽度不可配**：当前只支持 2 / 4 字节两种元素，缓存本身不能量化。

## Goal

让语言模型能够以 **INT8 权重**（weight-only 起步）构建并端到端推理，数值等价性有可核对判据，
并能自证引擎确实在执行低精度；在此基础上评估 K/V 缓存量化的收益与代价。

## Scope

### Included

- 权重量化的两种可选落地路线（原生图内量化 / 外部图量化）的选型与实现。
- 引擎侧的"真的在跑 INT8"自证：逐层精度可读 + 用例化断言。
- 与 FP32 基线的数值对比：逐 token 一致率 + logits 相对偏差（阈值**先量再定**）。
- 显存 / 引擎体积的量化对比（同一次构建对照，遵守既有测量协议）。
- K/V 缓存元素宽度的**可行性评估**（是否纳入本轮由 Gate-A 决定）。

### Excluded

- INT4 / GPTQ / AWQ / SmoothQuant 等外部量化算法（先评估本机可行性，不默认成立）。
- 激活量化与校准（除非所选路线必须）。
- K/V 缓存量化的 kernel 实现（若纳入，见 D3；它是独立里程碑）。
- 量化感知训练、精度-性能联合调参。
- 与其它模型的量化兼容性（只针对 GPT-2 做成闭环）。

## Acceptance Criteria

1. **端到端可跑**：语言模型以目标精度构建成功，并完成与 FP32 相同 prompt 的生成。
2. **自证低精度**：能从引擎读出的逐层精度证明量化层确实以低精度执行（不是静默回落）。
3. **数值判据**：与 FP32 基线的对比结果落在**有出处**的判据内；阈值必须在 P4 量出基线后
   按 `AGENTS.md` §7 写明来源（禁止直接复用视觉模型 INT8 的阈值——那是另一套口径）。
4. **资源下降**：权重占用的显存 / 引擎体积相对 FP32 有可测的下降（报实测值，不报估计值）。
5. **不回归**：FP32 / FP16 路径行为不变；现有沙箱用例全绿；真机既有用例不出现新红。

## Constraints

- 硬件：GTX 1660 Ti（sm_75 / TU116）**无 Tensor Core**；INT8 的收益来自带宽，不是算力。
- 6 GB 显存 → 量化本身带来的显存下降是主要收益之一，必须如实报。
- TensorRT 10.12 起 `kINT8` builder flag 与隐式校准路线已废弃 → 只能走显式量化节点。
- 判据纪律：不许放宽阈值、不许跨精度复用阈值（`AGENTS.md` §7）。
- 沙箱无 GPU：引擎构建与数值验收只能在真机完成（需批准）。
