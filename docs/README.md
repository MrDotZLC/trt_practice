# docs 目录地图与写作规约

> 本文是 `docs/` 的唯一入口：**文档怎么组织、事实写在哪、ID 怎么起**。
> 本文**不记录任何项目状态**——状态一律看 `PROGRESS.md`。
>
> 权威顺序：`AGENTS.md` > 本文（写作规约） > 各文档正文。
> 建立基线（2026-09-27，实测量得）：**本文之外的 21 份**共 13,005 行 / 1012 KB
> （5 份活文档 7766 行 + 16 份冻结文档 5239 行；本文自身不计入这个数）。
> 其中 `§x.y` 形式引用 1627 处、`#N` 形式引用 554 处、文件名提及 486 处；
> `docs/` 被仓外（代码 / 脚本 / 根 `README.md`）引用 **79 行 / 37 个文件**（已排除 `third_party/`）。

## 1. 先读什么（新会话阅读顺序）

1. `PROGRESS.md` 顶部的「当前基线」块 —— 现在在哪、测试基线是多少。
2. `PROGRESS.md` §6.6「当前未解决项」—— 哪些事还活着（它只是索引）。

6. 只要设计思路 → `mini_trt_llm_design.md`；只要某阶段的判据出处 → 对应的 `phaseN_*.md`。

> **不要从 `phase0` ~ `phase4` 的任何一份文档开始读。** 那 16 份全部已交付并冻结，
> 只作设计与判据出处，里面的"待办"早已过期。

## 3. 事实归属（SSOT：一个事实只写一次）

每类事实只有一个落点，其他地方**只放指针，不复制内容**。

| 事实类型 | 唯一落点 | 其他文档怎么写 |
|---|---|---|
| 现在在哪、测试基线、版本号、产物尺寸 | `PROGRESS.md` 的「当前基线」块 | 只写"见 `PROGRESS.md` 当前基线"；**不复制数字** |
| 架构决策与"为什么选 A 不选 B" | `PROGRESS.md` §2 | 链接 |
| 已交付了什么 | `PROGRESS.md` §3 | 链接 |
| 已知问题 / 坑的**结论**（问题 / 影响 / workaround） | `PROGRESS.md` §5 | 链接；**过程不写在这里** |
| 排查过程（命令 / 日志 / 对比数据 / 被否证的假设） | `TROUBLESHOOTING.md` | 只写 `TS-xxx` |
| 还没做什么 / 触发条件 / 优先级 | `future_iterations.md` | 只写 `OI-xxx` |
| 怎么做（任务分解 / 接口 / 破坏性清单） | `future_iterations_development_plan.md` | 链接 |
| 怎么验（用例清单 / 判据 / 执行口径） | `future_iterations_test_plan.md` 或对应 `phaseN_test_plan.md` | 链接 |
| 阈值本身 | 用例代码里阈值所在处（**原地写清出处**，AGENTS.md §7） | 只写出处链接 |
| 阈值的出处（哪次实测 / 哪个标准 / 哪份文档） | 该用例所属的**测试计划** | 链接 |
| 开工纪律 / 证据纪律 / 权限规则 | `AGENTS.md` | **不复述**，写"见 `AGENTS.md` §x" |

三条配套纪律：

- **数值类状态只能有一个出处。** 同一个基线数字出现在两份文档里，必然有一份先过期
  （本项目已因此吃过一次：旧总数 242 / 243 / 235 / 259 与现状 264 同时存在于 `PROGRESS.md`）。
- **纪律条款不复述。** 文档里重写一遍 AGENTS.md 的规则，改一次口径就要改 N 处。
- **结论与过程分家。** `PROGRESS` 只留结论 + 指向 `TROUBLESHOOTING` 的 ID；过程细节不进 PROGRESS。

## 4. 编号规约

### 4.1 为什么需要规约（实测冲突）

| 冲突 | 表现 |
|---|---|
| `P2` 双义 | 优先级 P2 vs 阶段任务 `P2-1` |
| `D1`~`D5` 多义 | phase1 / phase2 / phase3 / phase4 / future_iterations 各自独立定义，全仓 196 处 `Dn` 无法全局解析 |
| `§2.2` 双义 | `PROGRESS.md` 里是"定位：多模态框架"，`future_iterations.md` 里是"FlashAttention" |
| `S` 双义 | 沙箱测试层 S 层 vs 用例号 `S-14` |
| `B1-4` vs 批次 B | 真机用例号 vs 开发批次 |

根因是**跨文档引用只写 `§3.0j` 而不写文件名**——读者必须打开文档才知道指向什么，
于是章节编号一旦重排引用全部失效，编号被迫冻结。

### 4.2 规则

- **R1** 跨文档引用必须写成 `文件 + ID`，例如 `PROGRESS.md + DEC-INT8-WEIGHT-SOURCE`。
  **禁止**在跨文档语境里只写 `§3.0j` 或 `#46`。
  **存量豁免**：已经点名了目标文档的引用（如 `` 见 `PROGRESS.md` §2.13 ``）视为合规，**不强制回改**。
  2026-09-27 实测这类有 651 处，为"好看"批量重写只会制造没有信息量的 diff。
- **R2** `§` 只用于**同一文档内**导航，写法不变。
- **R3** **被跨文档引用过的标题**，在标题文本前置 `[ID]`；没被引用的标题不强制。
- **R4** ID 由"大写英文 + 短横线"组成，含义自明。**禁止** `ID-1`、`ITEM-A` 这类无语义编号。
- **R5** 老编号**保留在标题文本里**，让既有的 1627 处 `§` 引用继续可以搜到。
  **只加不改，不做批量重命名。**
- **R6** ID 的位置固定在**编号之后**：`### 3.0j [DEC-INT8-WEIGHT-SOURCE] 结案：…`。
  理由是保住 `^#{2,3}\s+号码` 这类既有检索方式——ID 放到最前面会把它们全部打断。

> **批 2 已收尾（2026-09-27）**：147 个被引用过的标题已挂 ID；**新写的跨文档引用一律用
> `文件 + ID`**。存量里"已经点名了目标文档"的 `§` 引用按 R1 的存量豁免保留（本文正文中出现的
> `PROGRESS.md §6.6` 之类即属此类），不强制回改。

### 4.3 前缀表（全仓唯一）

| 族 | 前缀 | 例子 | 归属文档 |
|---|---|---|---|
| 决策 / 结论锚点 | `DEC-` | `DEC-INT8-WEIGHT-SOURCE` | `PROGRESS.md` |
| 排查条目 | `TS-` | `TS-046` | `TROUBLESHOOTING.md` |
| 开放项 | `OI-` | `OI-INT8-ABS` | `future_iterations.md` |
| 计量点 | `MP-` | `MP-005` | 计划 / 测试文档 |
| 缺口 / 门 | `GAP-` | `GAP-G5` | `future_iterations.md` |
| 冻结阶段文档锚点 | `PH<n>` | `PH4-INT8-CRITERIA`、`PH1.5-ACCEPTANCE` | `phaseN_*.md` |
| 冻结设计文档锚点 | `DESIGN-` | `DESIGN-NATIVE-BUILD` | `mini_trt_llm_design.md` |

### 4.4 保持原样的本地编号

下列编号**不做全局唯一化**：它们在各自的文档语境里已无歧义，重命名是纯 churn。

- 阶段任务：`P0-1` ~ `P4-8`、`P1.5-0` ~ `P1.5-7`
- 用例号：`E1`~`E4`、`S-14`、`L0`~`L3`、`B1-4`、`T1`~`T3`
- 决策项：`Q1`~`Q15`、`F1`~`F4`、各阶段的 `Dn`
- 计量点旧名：`PF-n`、`PP-n`

**条件**：跨文档使用这些编号时，必须同时写出它所属的文档名（R1 已覆盖），不得只丢一个裸编号过去。

### 4.5 怎么找出"必须挂 ID"的标题

```bash
# 粗筛：列出所有跨文档出现的 § 目标，人工确认归属后再挂 ID
rg -n --no-heading '§[0-9]+(\.[0-9]+)*' docs/*.md | sort -u
```

判定标准：**被别的文档或代码引用过的标题**才挂 ID；同一份文档内部的导航不需要。
当前覆盖 **147 个**标题（文档侧 126 + 代码注释引用到的 19 个 + 补漏 2 个）。

**引用归属分类（2026-09-27 逐条判定的终态，全仓 1627 处 `§` 引用）**：

| 类别 | 处数 | 处理 |
|---|---|---|
| 同行点名目标文档（含"开发计划 / 测试计划"这类简称） | 921 | 合规，不动（R1 存量豁免） |
| 同文档导航（含显式"本文件 / 该文件 / 同文件"） | 684 | 合规，不动（R2） |
| 目标不在 `docs/`（引用 `AGENTS.md` 的章节） | 5 + 11 | 合规。**`AGENTS.md` 是合法引用目标**，见下方警告 |
| 目标编号全仓唯一、但没写文件名 | 0 | ✅ 已全部补名（原 130 处） |
| 落在代码块内（脚本注释） | 5 | 已逐条判：2 处补名、3 处是同文档引用，保留 |

> **警告（给做引用自检的人）**：`AGENTS.md` 也有 `§0.1`~`§0.7` / `§5` / `§7` 这些编号，但它不在
> `docs/` 里。任何"编号全仓唯一就补名"的自检脚本都会把这些引用误判成 `phase2_development_plan.md`
> 的 §0.6 之类（**2026-09-27 实际发生过一次**）。做自检时先把 `AGENTS.md` 加进合法目标集。

**判据演进留痕（用这套判据前先看这段）**：初版只扫 `##`/`###`，漏掉 78 个 `####` 四级标题；
第二版漏掉"开发计划 / 测试计划"这类**简称**；第三版没把 `AGENTS.md` 当合法目标。
三次修正把"待人工判定"压到 0：**438 → 202 → 130 → 0**。
**别相信一版判据就够**——每次下调都要问"是不是我的匹配又漏了一类"。

**自动补名这一批自己踩的坑（2026-09-27，已全部修回）**：一是对"已经是简称"的引用又插了一次文件名
（5 处）；二是 **`AGENTS.md` 的条目被误判**——在 `phase4_development_plan.md`、`PROGRESS.md` §4.6、
`phase2_supplement_plan.md` 各犯过一次。**这正是"130 处真歧义不要脚本猜"的直接证据**：连
"编号全仓唯一"这种强判据都会在这里翻车。

### 4.6 代码注释里的 docs 引用（2026-09-27 完成）

代码 / 脚本 / 构建脚本里引用 `docs/` 时与正文同规则：**路径 + ID**（`docs/TROUBLESHOOTING.md + TS-046`）。
本轮把 **69 行 / 35 个文件**（含 `src/core/`、`src/plugins/`、`include/`）里的 `§N` / `#N` 全部换成 ID 形式。

**两个坑**：① **有耦合的运行期字符串**——`thresholds["provenance"]` 同时出现在
`tests/test_resnet18_int8.cpp`、`tools/validate/int8_eval.py`、`tools/validate/README.md` 三处并被
`int8_crosscheck` 比对，**改一处必须三处同改**；② **同行的第二个引用**（`#18 / #17`、`§1.1/§1.3`）
拿不到文件名，必须单独处理。

**验证**：改动全部落在注释与那一个字符串常量上；增量编译 47/47 通过；沙箱 `ctest` **264 条 / 0 失败**
（与 `PROGRESS.md` 记录的基线一致）。

```bash
rg -n '^\s*#{2,3}\s+[0-9][0-9.]*[a-z]?\s+\[(DEC|TS|OI|MP|GAP|PH)' docs/*.md
```

## 6. 预算（超过就触发一次瘦身）

**口径 = 可见行数**（`<details>` 内不计）：折叠降低阅读面；按总行数考核会逼人删内容，而删掉的是出处（AGENTS.md §7）。

| 文档 | 现值（总 / 可见） | 上限（可见） | 超限动作 |
|---|---|---|---|
| `PROGRESS.md` | 1901 / **588** ✅ | **600** | 历史叙述折进 `<details>`，结论压成表 |
| `TROUBLESHOOTING.md` | 2971 / 2971（append-only） | 无上限 | 必须维护顶部索引（✅ 48 条已建）；单条 ≤ 80 行，超出折进 `<details>` |
| `future_iterations.md` | 817 / **377** ✅ | **400** | 已交付条目移出正文（只留索引行） |
| `future_iterations_development_plan.md` | 2123 / **574** ✅ | **800** | 已交付条目的计划段折进文末"附录：已完成" |
| `future_iterations_test_plan.md` | 677 / **344** ✅ | **350** | 同上 |
| `docs/README.md`（本文） | —（自引用，现值随编辑漂移，不登记） | **260** | 规约只留规则；实例与清单移进对应文档 |
| 16 份冻结文档 | 5303 / 5303 | 冻结，**不再增长** | 新结论一律回写活文档（含各 +4 行冻结横幅） |

瘦身优先级：**折叠 > 压表 > 移动**；删除是最后手段。

**折叠的三条自检**（2026-09-27 全踩过）：① `<details>` 配平（原文 `PROGRESS.md` 有一处
`> </details>` 坏闭合，把 §6.5~§7 吞了）；② **范围不得重叠**——`##`/`###` 一起折会让父级包住子级、
内容被**复制**（实测 dev plan 1932 → 3834 行）→ 只折 `###` 并断言范围不重叠；③ 折完做**内容行集合
对比**，消失的行必须能解释。

## 7. 冻结与归档

**冻结定义**：文档不再更新；只作设计与判据出处；不代表现状；新结论回写活文档。

**为什么原地冻结、不搬进 `docs/archive/`**：

- `AGENTS.md` §5 原文点名 `docs/phaseN_development_plan.md` 这个路径，而 `AGENTS.md` 不可擅改；
- 仓外有 79 行 / 37 个文件引用 `docs/`；
- 搬目录的唯一收益是好看，代价是一批产品代码注释的连带改动。

**冻结横幅模板**（加在文件第 1 行之后）：

```markdown
> **STATUS: ARCHIVED｜阶段已交付（<日期>）**
> 本文只作设计与判据出处，**不代表现状**；现状见 `PROGRESS.md`，排查见 `TROUBLESHOOTING.md`。
> 冻结后不再更新；确需修订时另开文档，并在 `docs/README.md` §2 登记。
```

## 8. 变更流程（改文档也照这个走）

1. **一次只做一批**，一批一次提交，保证能按批回滚。
2. **破坏性动作**（删除 / 覆盖既有章节）先一次性列清单等确认，见 `AGENTS.md` §0.5。
3. 改完自检：没有裸 `§` / 裸 `#` 跨文档引用；新增 ID 与 §4.3 前缀表一致。
4. 数值基线只改 `PROGRESS.md` 当前基线那一处；规约本身要改就改本文并在提交信息里说明理由。
